# 权限与升级兼容性修复记录（2026-10-06）

基线：`cd1cc3f0`，5.8.5；分支：`fix/permissions-compatibility`。本轮修复工作区代码，没有部署或修改正在使用的 Lertaro 安装与服务。

## 判断与 PR #332

高权限卷索引、服务代码写保护、按调用者身份过滤索引结果、管道对端校验有实际必要性。个人设置、普通搜索和托盘退出应在普通权限 App 中完成。管理员账户的全局管理命令在服务端校验，不能仅靠禁用 UI 控件。

PR #332 不建议原样合入：

- 必要性：症状需要修，但“服务持有目录句柄，所以 App 必然无法读 machine-settings.json”的根因说明不成立。目录加固使用的句柄会释放，正常共享数据 ACL 保留 Users 读取；真实普通进程在修复前后的隔离样本中均能读取正常权限的机器设置。不能用一份进程级设置缓存替代 ACL 与读写失败处理。
- 急迫性：索引/日志泄露、用户目录误锁、设置丢失和更新混合版本应优先修复；PR 所加启动缓存不是这些问题的完整修复。
- 代码质量：`Serve` 保存可变对象引用并长期优先于磁盘，缺少其他会话修改后的失效机制；返回的管道模型只有驱动列表，也不是完整机器设置。新增测试主要验证缓存引用，未验证实际 ACL、跨权限读写或多会话变更。启动额外等待 600 ms 的收益亦依赖尚未证实的根因。

本轮没有合并 PR #332；机器设置继续可读，保存权仍在服务端。权限/读取失败明确报告，不再冒充新安装默认值。

## 干净退出

托盘菜单保持可用，不因发现其他 App 进程而隐藏。退出过程不弹确认、不运行 runas、不请求 UAC：

1. 等待 Hook Stop 命令写入，关闭管道并停止重连。
2. 经同安装 App 身份校验的 `StopService` 请求让后台服务自行停止。标准账户也可执行此退出命令；SCM 的全局 STOP 权限不向任意进程开放。
3. 服务停止时关闭监听并结束它记录的所有会话 Hook，拒绝停止期间的新 Hook 启动。
4. App 等待 SCM 停止状态，再回 Dispatcher 退出；App 原有退出清理负责进程内服务。

实际隔离 Windows 服务验证：旧 `sc stop` 在普通权限返回 5（拒绝访问）；非 App 管道请求返回 Error、服务继续运行；普通权限 App 请求返回 Ok，SCM 为 Stopped，高权限 Hook 已退出。仅测试服务创建需要 UAC，退出请求没有提权。测试服务随后删除。

停止等待有 30 秒上界；不可达/身份不匹配/异常的服务不会被任意 PID 强杀，错误会进入日志。没有把这些异常情形伪装成“已确认停止”。

## 后续版本兼容规则

- 保持现有安装/便携数据位置及两种 SID 哈希识别，不因升级自动换数据根。
- 本轮修复权限 revision 为 2；完整修复失败不留下成功标记，下次重试。个人合法链接不得递归跟随或删除。
- JSON 根级未知字段保留；禁用插件的 PluginSettings 和禁用列表往返保留。未知嵌套模型字段及插件自己的序列化格式不在此保证内。
- 读不到、读坏和不存在是不同状态；只有主文件与备份均不存在才建立默认值。保存失败保留持久化配置，导入先验证。
- 服务保存驱动选择时合并权威机器配置，保留诊断级别与未来字段。不得把仅含驱动列表的管道模型作为整份机器配置写回。
- wire 保持 request v10 / response v6；StopService=21、GetServiceLog=22、ServiceLog response=10 为追加编号。已有编号与载荷不改；旧 peer 对未知命令返回 Error。改变既有载荷须升级协议。新功能需要同批更新的 App/Service。
- 跨机器或换账户时旧 SID 私有数据不自动向新账户开放，应以明确导入完成转移。未来备份应采用数据内容与版本信息，不能还原旧 SID/ACL。
