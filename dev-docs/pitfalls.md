# 维护经验

## 先证明问题

- 先读现有日志和采样，再加探针。与假设矛盾的证据应当推翻假设；提交标题、注释和外部分析都不能替代当前实现与复现。
- 确认日志来自正在运行的那份程序，并核对进程、版本和日志级别。决定性的诊断不能依赖用户未开启的 Debug 开关。
- 插桩本身会改变时序，尤其是 UI 线程、锁内日志和进程级分配计数。回答完问题后移除一次性探针。
- 修复需要覆盖完整用户路径：证书能加载不等于 TLS 能握手，集合顺序正确不等于真实窗口首屏变快，取消等待不等于插件已停止。
- 放宽匹配门槛时，按短词、简拼、多词、长文件名等查询形状检查全量语料。小探针用于定位，不用于外推召回率与噪声。
- 缺失依赖用移除后执行真实路径来证明；性能比较同时检查结果条数、内容和顺序，避免把少做了正确工作当作加速。

## 构建与验证

- [Lertaro.slnx](../Lertaro.slnx) 只包含产品工程；测试入口是 [Tests/Tests.slnx](../Tests/Tests.slnx)。产品构建不会更新测试 DLL，跳过构建前必须确认对应测试产物已更新。
- 退出码 0 不等于执行了测试。查看发现数、实际用例名与 TRX；空测试工程和未匹配的筛选条件不能算通过。
- STA 测试不天然共享同一线程，也不天然隔离静态状态。11 月 10 日复核发现 `ExplorerStaInvokerTests` 并行修改共享弃读计数，串行运行才通过；不能用扩大超时掩盖共享状态问题。
- 只需 HWND 的 WPF 验证使用 `EnsureHandle()`，避免可见测试窗口抢前台、影响其他用例。真正的焦点、DPI、宿主交互另做真机验证。
- 发布流水线目前负责构建与发布，本地仍需完成受影响测试。不要把历史全绿计数当作当前状态，也不要把 NU1900 等审计请求失败写成漏洞检查通过。
- 行尾由 [.gitattributes](../.gitattributes) 与 [.editorconfig](../.editorconfig) 统一为 LF。格式检查限定改动文件，避免无关重排。

## 实现与交付

- 修机制前先找标准库、平台能力和现有依赖。跨层问题不要靠再加一个用户开关掩盖；有意保留的上限用 `ponytail:` 写明代价和重开条件。
- 改动副作用调用顺序时，重新检查下游早退条件、初始化状态与资源生命周期。窗口复用会把“每窗口一次”变成“每进程一次”。
- 缓存必须说明身份、失效条件与所有权。缓存不可变匹配证据时，仍要更新 UI 行的元数据、动作参数、选择和高亮。
- 合并冲突逐块看三方内容，随后核对语义；整份选择一侧可能吞掉另一侧已修复的行为。文档以代码为准。
- 插件依赖要进入实际打包清单，并从部署目录验证；临时预览工程能加载，不代表发布包完整。
- 诊断只收足够判断的最小信息。设置和排序导出含路径、查询或令牌，进入报告与回放夹具前先脱敏。

## 文案与站点

- 用户可见名称先查对应语言资源，七种受支持语言同步修改。不要把查询语法、索引规则和插件过滤规则混写成一套。
- Unicode 标题看起来相同，NFC/NFD 仍可能产生不同锚点。站点标题与目录锚点使用同一归一化规则；改锚点后构建并检查链接。
- 产品特有边界见各主题文档；这里不再复制排序、权限和窗口的细节。
