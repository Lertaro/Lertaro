# 正则审计修复与历史测量

2026-11-10 对 R1–R8 的修复记录，起点为 `0a87b10f`，基于当时的 main `5f735e70`。本页测量使用该次审计与修复后的产品 DLL；样本及 SHA-256 见 [search-regex-fixes-results.json](search-regex-fixes-results.json)。修法在 2026-11-21 rebase 后保留，当前契约见 [search-grammar.md](search-grammar.md)，缺陷反例见 [增量审计](search-regex-incremental-audit.md)。

## 修复方案

| 项目 | 已实施方案 |
| --- | --- |
| R1 别名绕过名称条件 | 标题直接匹配保留 OR 语义；进入 alias、关键词或 shadow 前验证原标题，再用缓存的正向词视图匹配其他表示 |
| R2 按到达顺序丢行 | 完整窗口请求全量索引候选，accumulator 保留候选；最终排名、标记、侧栏和列排序后展示最多 8,000 行，原列表继续用于重新筛选 |
| R3 重复耗尽回溯预算 | 一次超时使解析查询失败，后续匹配抛 `SearchRegexTimeoutException`；失败状态按子句数组弱键保存，与共享编译缓存分离，并跨多盘、实时目录及管道传播 |
| R4 高亮重复解析 | 按完整查询缓存普通词与正则计划，继续按精度、AND/OR 设置和 alias revision 失效 |
| R5 实时搜索丢失裸盘符 | 完整查询使用 `Parse`，路径尾片段使用 `ParseText`；按候选路径核对盘符，冷扫描与缓存重放一致 |
| R6 正则被归一化改写 | 先提取原文子句，再归一化普通词；名称各入口与高亮传递原始字符，对会被归一化改写的必需字面量放弃预筛 |
| R7 淘汰扫描未被等待 | 活动任务独立跟踪，直接使用 owner token；关闭时禁止注册，在锁外取消并有界等待 |
| R8 非法阈值处理不一致 | 空阈值只排序，非空非法值不认领且直接调用也返回空；folder 阈值限于 f/folder/dir，大小拒绝负数及溢出值 |

共享冷目录扫描遇到首个查询超时后，停止该请求的匹配与投递，通过独立失败任务通知调用者，继续收集原始目录供后续查询复用。高亮回调超时停止该计划的正则绘制。已经进入 Regex 的并行匹配各自退出；回退引擎的 250 ms 预算按单次匹配计。

关闭缓存最多等待 2 秒，包含已淘汰的活动任务；卡在不可取消文件调用中的任务仍可能超过该上限。失败帧与配套协议版本见 [windows-integration.md](windows-integration.md)。

## 回归中保留的对照

- 合格标题 `target.pdf` 配别名 `report` 可满足 `report /\.pdf$/`；不合格标题 `blocked.txt` 配别名 `report.pdf` 被拒绝。
- 第 8,001 行是最佳行时仍进入展示；标记或侧栏最终只留这一行时，超限提示消失，列排序也能重新使用全部候选。
- `/^Ａ$/` 与 `/^\uFF21$/` 均匹配全角 Ａ，拒绝半角 A；普通词 A 继续按既有折叠匹配全角。NFD `e\u0301` 的正则与高亮使用原始两码元。
- 正常 `report` 每万次 mask 仍标记 60,000 字符，两个正则场景各标记 100,000 字符。窗口失败状态替换部分结果，旧查询的迟到失败不能覆盖新查询。

## 对照测量

Windows 10.0.26300、SDK 10.0.403、12 逻辑处理器，Release，`DOTNET_TieredCompilation=0`。before 为审计产物，after 为当时修复后的产物；3 对独立进程交替执行，采样期间不并行构建或测试。

索引固定 60,000 文件（6,000 report、54,000 notes），limit=204，预热 3 次，每轮 10 个样本，共 30 个。每次返回 204 行。分配为进程总分配增量除以查询次数。

| 查询 | before 中位 ms | after 中位 ms | before→after p95 ms | 每查询分配 B：before→after |
| --- | ---: | ---: | ---: | ---: |
| `report` | 3.213 | 3.313 | 7.084 → 6.971 | 2,077,014 → 2,057,342 |
| `rprt` | 5.282 | 5.489 | 6.819 → 6.574 | 2,660,227 → 2,607,386 |
| `archive report` | 1.756 | 1.750 | 2.567 → 2.804 | 1,421,828 → 1,394,576 |
| `/report/` | 5.182 | 5.611 | 6.103 → 6.481 | 4,932,250 → 4,986,342 |
| `/report.*\.txt$/` | 5.338 | 5.615 | 6.246 → 5.969 | 5,005,142 → 4,925,290 |
| `report /\.txt$/` | 8.836 | 8.878 | 9.774 → 9.840 | 7,283,355 → 7,332,650 |
| `/.*[0-9]/` | 31.071 | 30.856 | 32.404 → 33.498 | 39,795,486 → 40,257,948 |

普通查询和大多数正则耗时处于相近量级，部分 p95 上升。`/report/` 中位增加约 0.43 ms（8.3%）；无必需字面量的正则仍需扫描更多名称。主要优化收益在高亮计划复用与重复回溯的终止。

高亮预热 100 次，每样本 1,000 次 mask，共 30 个样本；分配按每轮 10,000 次统计中位：

| 查询 | 每千次中位 ms：before→after | 每万次分配 B：before→after |
| --- | ---: | ---: |
| `report` | 0.317 → 0.305 | 960,872 → 960,872 |
| `report /\.txt$/` | 1.970 → 0.740 | 13,365,992 → 1,440,784 |
| `/report.*\.txt$/` | 1.698 → 0.548 | 13,288,672 → 960,784 |

带扩展名子句的高亮分配减少 **89.2%**，中位耗时减少 **62.4%**，来自分割与解析计划复用。

病理模式 `/^(?=(a+)+$)/` 对 `a×30 + !` 连续调用四次，三轮中位 **1,005.5 → 261.7 ms**。修复后首次匹配耗尽预算，后三次立即报告查询失败；新解析查询仍可成功匹配简单名称。

R2 另测候选保留成本：每批 1,000 行、预热 2 次、每轮 5 个样本，共 15 个。计时覆盖输入记录构造、装饰与排序合并，分配包含被丢弃的输入记录。

| 输入候选 | 保留行 before→after | 中位 ms before→after | 分配 B before→after | 最后一行保留 before→after |
| ---: | ---: | ---: | ---: | --- |
| 8,000 | 8,000 → 8,000 | 8.145 → 6.261 | 3,064,568 → 3,064,568 | 是 → 是 |
| 50,000 | 8,000 → 50,000 | 16.037 → 56.355 | 14,506,376 → 19,904,720 | 否 → 是 |

8,000 行的耗时在先导与最终轮次间波动，分配一致。50,000 行保留完整候选使耗时与分配增加；8,000 展示限额不限制候选内存。

## 回归与复现

现有回归覆盖 `RegexPrefilterTests` 的 base/delta、路径及 Unicode，`RegexTimeoutTests` 的查询隔离，本地/网络多盘异常传播，`SearchRegexFailureTests` 的两种响应协议，以及 `LiveDirectorySearcherTests` 的冷/热匹配。`LiveScanCacheTests` 覆盖淘汰与失效后的关闭。App 覆盖标题/关键词/shadow、高亮、最终展示和旧查询保护；排序 provider 覆盖非法阈值与未完成输入。

按当前 runner 运行受影响测试，保留 TRX/binlog。性能采样使用 Release、固定语料及独立进程，同时核对结果条数、有序签名和实际加载程序集的哈希。

JSON 保留历史样本。基线 DLL 与一次性探针未入库，重现历史差值需配套原产物；重新比较时保存自己的基线及探针。历史 Core 串行条件和 NU1900 记录见 [pitfalls.md](pitfalls.md)。
