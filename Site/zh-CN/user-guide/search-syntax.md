# 搜索语法

Lertaro 的搜索框远不止支持简单的纯文本检索。它配备了极速的匹配算法，支持模糊跳跃匹配、布尔逻辑、排除、盘符与路径限定、排序与过滤查询标记以及多语言别名。所有这些语法都可以在同一条查询中自由混用。

## 1. 基础匹配与大小写

### 模糊匹配（默认）

Lertaro 默认启用模糊匹配。只要按顺序输入任意字符，即使这些字符分散在文件或文件夹名称的各处也能命中：

| 输入示例 | 匹配结果 | 说明 |
| :--- | :--- | :--- |
| `ltro` | `Lertaro.exe` | 字符按顺序命中：`l` → `t` → `r` → `o`（**L**er**t**a**ro**.exe） |
| `vsc` | `Visual Studio Code.lnk` | 命中每个单词的首字母（**V**isual **S**tudio **C**ode） |
| `rt-fin` | `Q3-report-final.docx` | 命中连续子串（Q3-repo**rt-fin**al.docx） |

在 **设置 → 通用 → 系统 → 启用模糊匹配** 中关闭该开关后，每个普通词都要求连续子串——输入 `abc` 只会匹配名称中包含连续 `abc` 的项，不再匹配 `a-b-c`。该开关只影响普通词和排除项，下文的标记语法在任何设置下都不受影响。

### 大小写不敏感

匹配始终忽略大小写，而且是双向的——你输入时的大小写永远不会改变命中范围，文件名自身的大小写也不会。`myfile`、`MyFile` 与 `MYFILE` 彼此都能互相命中。

不存在大小写敏感模式：输入大写字母永远不会把某个词收窄为精确大小写匹配。

### 拼音别名与排序

中文名称可以用拼音检索，有两种形式：**简拼**（每个字一个字母，如「恶性」的 `ex`）和**全拼**（把每个音节完整拼出，如「证书」的 `zhengshu`）。

**排序：匹配位置 > 覆盖率 > 英文 > 简拼 > 全拼。** 匹配起点越靠左越优先；其次是更紧凑、更完整的匹配；英文/简拼/全拼只能用来区分在前面两项上已经打平的结果。所以英文命中不再自动优先于拼音命中——只有当两者位置同样靠前、紧凑程度也相同时才会优先。最后一个音节只输入一部分仍然能命中，因此在你还在输入时 `zhengsh` 依然能持续找到「证书」。

**关闭模糊匹配时**，拼音匹配必须对齐词的开头。`ex` 能找到「恶性」（两个字的首字母），但找不到「学习」（那需要把 `xue` 的结尾拼接到 `xi` 的开头）。开启模糊匹配时，这种松散读法正是你所要求的，依然可用。

## 2. 多词与布尔逻辑

### 空格：AND

用空格分隔多个搜索词，表示必须同时满足所有条件。这些词在文件名中出现的先后顺序**无关紧要**：

```text
report final 2024
```

上述查询既能命中 `2024-Q3-report-final.docx`，也能命中 `final_report_2024.pdf`。

### 竖线 `|`：OR

用竖线符号 `|` 分隔多个词，命中其中任意一个即可：

```text
png | jpg | gif
```

你可以自由组合 AND 与 OR 逻辑：

```text
report | summary
```

这会找到匹配 `report` 或 `summary` 的文件。在 OR 查询中，命中分支里的所有匹配词都会在结果名称中同时高亮。

### 运算优先级：AND 比 OR 结合得更紧

当空格（AND）与竖线 `|`（OR）混合出现在同一条查询中时，默认情况下空格结合得**更紧**：每一段由空格分隔的词会先 AND 成各自的分组，然后这些分组之间再取 OR。不支持括号，而这正是标准的布尔读法——但旧的结合顺序只差一个开关（见下）。

```text
report | summary 2024 | draft
```

等价于 `report OR (summary AND 2024) OR draft`。

这正是「先输入几个备选项、再对其中一个加限定」的用户所期望的读法：`summary 2024` 会保持为一个整体条件，而不会散成两个彼此独立的备选项。

#### 切回 OR 优先

在 **设置 → 通用 → 系统 → OR 优先于 AND（旧行为）** 下，你可以恢复 Lertaro 历史上的结合顺序，即竖线比空格结合得更紧：

```text
report | summary 2024 | draft
```

此时表示 `(report OR summary) AND (2024 OR draft)`。

该开关只改变这两个运算符之间的优先级——不引入任何新运算符，而且对只使用其中一种运算符的查询没有任何影响（无论采用哪种设置，`read me` 与 `readme | rdm` 含义都相同）。

注意：`|` 必须是两侧都带空格的独立标记——`a|b` 或 `a |b` 不会被解析为 OR。这一点同样适用于排除项：`b | :c` 会被读作「b，或者非 c」，所以若想把某项从整条查询中排除，请让排除项占据自己独立的空格分隔位置（`b :c`）。

#### 优先级不受引号影响

没有任何引号语法能改变优先级的读法；分组方式完全由上面的设置决定。只有当 `|` 是两侧带空格的独立标记时它才是 OR，所以把它写进普通文本（如 `data|backup`）只会搜索这个字面字符串。

### 空格规则

没有办法把空格放进单独一个词里。空格永远是 AND 分隔符，因此带空格的查询永远是若干个 AND 词——这是 Lertaro 唯一一处会把标点读作结构的地方：

```text
final report
```

是 `final` AND `report`，与把它们当作一个短语 `final report` 并不相同。

**引号和反斜杠都解决不了这个问题。** `'final report'` 和 `"final report"` 不是短语语法：引号会作为字面字符参与匹配，所以这类查询是在找名称里含有引号的文件，结果只会是空。`final\ report` 同样会被读成 `final` AND `report` 两个词。

结论是 Lertaro 没有精确短语搜索。当这两个词在你想找的名称里相邻时，搜更有辨识度的那一半、让排序把它顶到前面即可——或者使用正则子句，它会把名称当作一个整体来匹配（见下文）：

```text
/^final report/
```

### 粘贴多行文本折叠为 OR

当你复制多行文本（例如来自电子表格、文本文件或日志的文件名）并直接粘贴到搜索框时，Lertaro 会自动把这些行用 `|` 折叠成一条 OR 查询（空行会被自动跳过）：

```text
123
456
678
```

粘贴后自动变为：

```text
123 | 456 | 678
```

## 3. 搜索运算符速查表

### 运算符表格

| 运算符 / 语法 | 类型 | 说明 | 输入示例 |
| :--- | :--- | :--- | :--- |
| *(无)* | 默认词 | 开启模糊匹配时为模糊，关闭时为精确子串 | `report` |
| `:` | 排除 | 剔除名称中包含该文本的所有结果（始终精确，绝不模糊） | `:temp` |
| `\|` | OR 逻辑 | 匹配竖线任意一侧 | `doc \| pdf` |
| `/.../` | 正则表达式 | 用 .NET 正则表达式匹配名称（见下文） | `/^report.*\.md$/` |
| `*` | 绕过排除 | 对你已配置的排除规则做一次性豁免（仅首字符生效） | `*node_modules` |
| `<` `>` | 排序 / 过滤标记 | 对结果排序并可选择过滤（见[第 5 节](#_5-查询标记-排序与过滤)） | `<s>20m` |
| `\` | 插件标记 | 应用插件提供的过滤器，例如文件分类（见[第 5 节](#_5-查询标记-排序与过滤)） | `\audio` |

### 运算符详细行为与组合

1. **排除 `:`** —— `:term` 会剔除名称中包含 `term` 的所有结果。排除项写在冒号后**不带空格**（写成 `:temp`，而不是 `: temp`），而且它不能是查询中唯一的内容：因为排除只能移除结果，一条只有排除项的查询什么也显示不出来。实践中这意味着总要至少保留一个普通词与它并列。
2. **排除始终精确** —— 即使开启了模糊匹配，它们也按连续子串匹配，并且不会通过拼音别名展开。否则一个松散子序列或一处拼音拼写就会移除你从未指名的文件。
3. **单独的冒号会被忽略** —— 后面什么都没有的 `:` 不是运算符，只会被从查询中直接丢弃。
4. **盘符冒号是另一回事** —— 盘符跟在冒号后面（`d:`，见[第 4 节](#_4-路径模式与盘符限定)），而排除项写在冒号前面（`:temp`）。两者永远不会混淆，而单词内部的冒号（`c:\path`）是普通文本。
5. **正则子句会在其他任何东西读取查询之前先被提取出来** —— 这正是它的反斜杠和斜杠不会被误认为路径的原因，也意味着子句可以出现在查询中的任何位置（`/\.md$/ report` 与 `report /\.md$/` 是同一次搜索）。

**运算符组合示例**：

- `report :draft`：找出名称包含 `report` 的结果，并剔除其中名称包含 `draft` 的。
- `IMG :png :gif`：找出名称包含 `IMG` 的结果，同时剔除 `png` 和 `gif` 文件。两个排除项之间是 AND——只有两者都不包含的名称才能留下。
- `log :temp :bak`：保留既不是临时文件也不是备份文件的 `log` 文件。

### 正则表达式（`/.../`）

在两个斜杠之间写一个 .NET 正则表达式，即可完全按你的描述匹配文件**名称**：

```text
/^report.*\.md$/
```

这会找出以 `report` 开头并以 `.md` 结尾的名称。该子句会与查询的其余部分做 AND，因此 `report /\.pdf$/` 只会在 `report` 的命中里保留 PDF。

有四件事值得了解：

- **它匹配的是名称，而不是路径**，也不是文件内容。文件夹请使用路径查询。
- **它不会经过拼音别名。** 正则表达式描述的是名称中实际存在的字符，所以中文名称由它自身的字符匹配，而不是由这些字符的拼音拼法匹配。
- **斜杠是分隔符，而 `\` 用于转义。** 字面点号要写成 `\.`（单独的 `.` 表示任意字符）。要匹配字面斜杠，请写成 `\/`。由于 `/` 同时也是 Windows 的备用路径分隔符，子句必须是一个以 `/` 开头并以 `/` 结尾的完整词，而且体内未转义的 `/` 会提前闭合子句——这正是 `C:/Users/me`、`/mnt/c/Users`、`/usr/local/` 这类前斜杠路径仍然按普通路径处理、不会被当成正则的原因。未闭合的子句会被当作普通文本，而不会吞掉查询的其余部分。
- **正则表达式无法像普通词那样被加速**，因为它不是固定字符串。Lertaro 会提取表达式所要求的最长字面字符序列——从 `/\.exe$/` 中提取 `.exe`，而从 `/^(ogg|mp3)$/` 中什么也提取不到——并用它跳过大多数候选，然后才运行真正的表达式。在无字面字符的正则旁再加一个普通词，是让这类搜索保持快速的可靠办法。

## 4. 路径模式与盘符限定

### 指定盘符

在查询开头写入盘符加冒号，可以把结果严格限定在该盘内：

```text
d: report
```

盘符必须是一个**独立的双字符标记**：冒号后面必须跟一个空格。`d:report` 不再是盘符限定——它是一个按字面文本 `d:report` 搜索的普通词，因为从前两个字符猜测盘符会产生误命中。只识别 ASCII 字母，所以 `中: x` 也不是盘符。

### 完整路径模式

当查询中包含路径分隔符（`\` 或 `/`）时，Lertaro 会自动切换到全路径匹配模式：

```text
D:\Projects\Lertaro
```

以路径分隔符结尾（如 `D:\Projects\`）会搜索该文件夹**内部**的直接内容。

> [!NOTE]
> 插件标记同样以 `\` 开头（例如 `\audio`）。在决定是否进入路径模式之前，标记就已经被从查询中提取出来，因此只包含标记和普通词的查询（`report \audio`）仍是一次普通的名称搜索。只有当剩余文本中还留有分隔符时，才会触发路径模式。

### 上级文件夹回退匹配

当仅按文件名搜索无法填满结果容量时，Lertaro 会自动用未在文件名中命中的查询词去匹配上级文件夹名称，无需任何特殊语法：

```text
d01j dcj
```

即使 `dcj` 从未出现在文件自身的名称中，Lertaro 也能找到位于名为（或别名为）`dcj` 的文件夹中的 `d01j.txt`。

> [!NOTE]
> 这要求至少有一个词命中文件名本身，并且只在仅名称匹配未填满结果时才触发。回退结果始终排在文件名直接匹配之后。

## 5. 查询标记：排序与过滤

查询标记是以 Windows 文件名中不可能出现的字符开头的词，因此它们永远不会与你想要搜索的文本混淆。它们分为两族：

| 族 | 触发字符 | 示例 | 归属 |
| :--- | :--- | :--- | :--- |
| 排序 / 过滤 | `<` 和 `>` | `<s>20m` | `CoreExtensions` 插件 |
| 插件标记 | 你配置的 **插件标记前导字符**（默认 `\`） | `\audio` | 认领该标记的那个插件 |

### 标记可以出现在查询中的任何位置

标记**不必**放在末尾。以下写法彼此等价：

```text
report <s>20m \audio
<s>20m report \audio
\audio report <s>20m
```

只有当标记是**整个词**并且位于词首时才算数——`abc\def` 是普通文本，不是标记。

### 排序与阈值（`<` 和 `>`）

第一个字符决定排序方向，紧跟其后的字母决定属性：

| 标记 | 含义 |
| :--- | :--- |
| `<s` | 按大小排序，最小在前 |
| `>s` | 按大小排序，最大在前 |
| `<c` / `>c` | 按创建时间排序，最旧 / 最新在前 |
| `<m` / `>m` | 按修改时间排序，最旧 / 最新在前 |
| `<a` / `>a` | 按访问时间排序，最旧 / 最新在前 |
| `<f` / `>f` | 文件夹在前 / 文件在前 |

再加上第二个触发字符和一个阈值，就可以只保留其中的一侧：

| 标记 | 含义 |
| :--- | :--- |
| `<s>20m` | 大于 20 MB 的文件 |
| `<s<20m` | 小于 20 MB 的文件 |
| `>c>2008.8.3` | 创建时间晚于 2008-08-03 的项 |

第二个触发字符是**比较**，而不是重复排序箭头：`>` 始终表示下界，`<` 始终表示上界。

大小接受 `k`、`m`、`g` 和 `t` 后缀（二进制单位，因此 `1m` 就是 1 MiB），也可以直接写字节数。文件夹/文件键的阈值使用 `f` / `folder` / `dir`。

日期必须**年在前**。以下写法均被接受（两位年份会读作 `20xx`）：

| 分隔符 | 年份宽度 | 月/日宽度 | 示例 |
| :--- | :--- | :--- | :--- |
| `-` | 4 或 2 | 补零或不补零 | `2003-01-03`、`2003-1-3`、`03-1-3` |
| `.` | 4 或 2 | 补零或不补零 | `2003.01.03`、`2003.1.3`、`03.1.3` |
| `/` | 4 或 2 | 补零或不补零 | `2003/01/03`、`2003/1/3`、`03/1/3` |
| 无 | 4 | — | `20030103` |

分隔符不得混用（`2003-08.03` 不是日期），并且不接受月在前面的读法 `01-03-2003`——顺序始终是年、月、日，因此同一条查询在两台机器上永远不会表示两个不同的日期。只写年份（`2008`）和年-月（`2008.8`）的形式也被接受，分别表示“2008 年内”和“2008 年 8 月内”。

### 插件标记（`\`）

插件标记由插件提供，每个标记的含义由各插件自行决定。内置的 `CoreExtensions` 插件提供了文件分类过滤器：

- `\doc`：文档（`*.doc; *.docx; *.pdf; *.txt; *.ppt; *.pptx; *.xls; *.xlsx; *.csv; *.rtf; *.md; *.wps`）
- `\img`：图片（`*.jpg; *.jpeg; *.png; *.gif; *.bmp; *.webp; *.ico; *.svg; *.tif; *.tiff; *.psd; *.ai`）
- `\video`：视频（`*.mp4; *.mkv; *.avi; *.mov; *.wmv; *.flv; *.m4v; *.webm; *.3gp; *.rmvb; *.ts`）
- `\audio`：音频（`*.mp3; *.wav; *.flac; *.aac; *.ogg; *.m4a; *.wma; *.ape`）
- `\zip`：压缩包（`*.zip; *.rar; *.7z; *.tar; *.gz; *.bz2; *.xz; *.iso; *.wim; *.esd`）

**示例**：

- `financial \doc`：在文档中搜索 “financial”。
- `wallpaper \img`：在图片中搜索 “wallpaper”。

你可以在 **设置 → 插件 → CoreExtensions** 下重命名分类、修改每个分类覆盖的扩展名，或者添加自己的分类。关键字本身按最长优先匹配，因此 `\a` 规则和 `\audio` 规则可以共存，而 `\audio` 依然胜出。

前缀字符可在 **设置 → 通用 → 系统 → 插件标记前导字符** 下配置。它不能为空，不能是 `<` 或 `>`，也不能与其他插件自己的前缀相同——设置界面会报告冲突，而不是让某个提供者悄悄胜出。

完整搜索窗口左侧的类型过滤侧边栏在同一插件的 **搜索过滤器** 分组中单独配置。侧边栏过滤器名称仅用于显示；前缀引用只在侧边栏过滤器规则内部解析，并指向 **自定义过滤器** 列表中的关键字，包括已停用的自定义过滤器。

### 链式标记

因为标记是彼此独立的词，一条查询里可以出现多个，每一个都会依次生效：

- `report \doc >m`：搜索 “report”，只保留文档，按修改时间排序（最新在前）。
- `backup \zip <s`：搜索 “backup”，只保留 `.zip` 压缩包，按大小排序（最小在前）。
- `icon \img <s>1m`：搜索 “icon”，只保留大于 1 MB 的图片，最小在前。

## 6. 特殊搜索功能

### 单次搜索绕过排除规则

在查询前加上 `*`，可以在本次搜索中临时绕过你在[**排除规则**](./settings/index-drives#_5-排除规则-exclusions)里配置的路径排除、glob 和正则表达式，而无需修改设置：

```text
*node_modules
```

开头的 `*` 会在匹配前被剥离。这只能召回已经索引过的文件（网络盘/WSL 盘上从未被索引的排除路径不会出现）；系统/隐藏文件过滤仍然生效。注意这是应用自身的排除**规则**，与查询中的 `:` 排除词是两回事。

### 结果类型触发符

在 **设置 → 通用 → 快速搜索窗口 → 结果类型优先级** 下，你可以为特定结果类型（应用程序、设置、文件分类、插件、文件等）配置一个单字符**触发符**。

在快速搜索窗口中把该触发符作为第一个字符输入，就只会显示那一种结果类型，其余全部隐藏：

```text
;vs
```

如果 `;` 被分配给“应用程序”，上述查询就只在应用程序中搜索 Visual Studio。触发符必须是第一个字符，前面不能有任何内容，并且只对快速窗口和内嵌窗口生效。在这两个窗口中，无论触发符如何，历史记录和收藏夹都始终固定在顶部。

> [!NOTE]
> 触发符必须是查询的第一个字符——在它前面放插件标记或排序标记（`\img ;vs`）会让触发符不被识别，因为查询已经不再以它开头。

## 7. 多语言别名

### 中文文件名：拼音别名

中文文件名随 `PinyinAlias` 插件一起内置，开箱即用，无需任何配置即可用拼音检索：

- **全拼**：输入 `chongqing` 可匹配 `重庆.docx`。
- **拼音首字母**：输入 `cq` 同样匹配 `重庆.docx`；输入 `wzry` 匹配 `王者荣耀.exe`。
- **多音字**：常见读音都会被自动索引（例如 `重庆` 同时匹配 `chongqing` 和 `zhongqing`）。

你可以在 **设置 → 插件** 下确认 `PinyinAlias` 是否处于启用状态。

### 西班牙语文件名：重音别名

带西班牙语重音字符（`á`、`é`、`í`、`ó`、`ú`、`ü`、`ñ`）的文件名随 `SpanishAlias` 插件一起内置，可以直接用不带重音的 ASCII 字母搜索：

- 输入 `cancion` 匹配 `Canción.mp3`。
- 输入 `nino` 匹配 `Niño.txt`。
- 输入 `ciguena` 匹配 `Cigüeña.png`。

命中的字符（包括原文件名中的重音元音）都会被准确高亮。可在 **设置 → 插件** 下管理该插件。

## 8. 常见问题与收藏夹

### 收藏夹，而非自定义别名

Lertaro 没有提供通用的“自定义搜索别名/宏”机制。最接近的原生方案是：

- [**收藏夹**](./settings/favorites)：把任意文件、文件夹或网址以自定义显示名称固定下来，就能用该自定义标题搜到它（结果中带有 ★ 图标）。
- **文件过滤器**（见[**即时答案**](./instant-answers#_5-文件过滤器)）：把触发关键字绑定到选定的文件夹，之后在快速搜索窗口输入 `keyword term` 即可把一次普通的索引搜索限定在这些文件夹内。

如果你想用自定义关键字触发自定义脚本或启动程序，请见[**自定义命令**](./instant-answers#_6-自定义命令)。
