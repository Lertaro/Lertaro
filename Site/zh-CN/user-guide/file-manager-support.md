# 支持的文件管理器

Lertaro 不只是能搜索——它还可以和你正在使用的文件管理器或对话框进行集成。根据目标窗口的不同，集成最多可以提供以下三种能力：

- **内嵌搜索** —— Lertaro 的搜索框会直接嵌入目标窗口(也就是[内嵌窗口](./getting-started#三种窗口))，不用离开它就能搜索。
- **快速导航** —— 目标窗口会响应[快速导航的鼠标触发方式](./hotkeys#快速导航鼠标)(双击/中键，或者内嵌窗口自带的图标)，弹出一个包含收藏夹、历史记录和快捷文件夹的级联菜单。
- **活动路径检测** —— Lertaro 能识别目标窗口当前打开的是哪个文件夹，从而把搜索范围限定在该文件夹内，并让复制路径这类基于相对路径的动作能正确解析。

并不是每种集成都同时提供这三种能力——具体见下表。

## 快速导航中的已打开文件夹

在 Folder Cascader 插件中开启**显示已打开的文件夹**后(默认开启)，快速导航会在收藏夹和历史记录之前加入**当前打开的文件夹**分组。它会汇总所有受支持文件管理器当前打开的真实文件系统目录，并自动去除重复路径。虚拟位置和已经不存在的目录不会显示，因此列表中的每一项都可以正常跳转。

## 内置(无需额外安装)

以下几项都随 Lertaro 的核心扩展插件一起提供，不需要单独启用。

| 目标 | 内嵌搜索 | 快速导航 | 活动路径检测 |
|---|---|---|---|
| Windows 文件资源管理器 | 支持 | 双击或中键 | 支持 |
| 现代打开/保存文件对话框 | 支持(这个对话框本身就是内嵌窗口) | 中键，或左键点击内嵌窗口自带的图标 | —— |
| 经典打开/保存文件对话框 | 支持 | 中键，或左键点击内嵌窗口自带的图标 | —— |
| 经典浏览文件夹对话框 | 支持 | 中键，或左键点击内嵌窗口自带的图标 | —— |

活动路径检测对这几个对话框本身没有意义——一旦 Lertaro 已经嵌入对话框里，就不存在另一个"其它窗口"可供它检测并作为搜索范围了。

## 可选插件(设置 → 插件)

下面每一项都是独立的插件。在[设置 → 插件](./settings/plugins)里安装/启用，然后在该插件自己的**配置**对话框里分别开关**启用内嵌搜索**和**启用快速导航**——两者默认都是开启的。

| 目标 | 内嵌搜索 | 快速导航 | 活动路径检测 |
|---|---|---|---|
| Directory Opus | 支持 | 在文件列表区域点击中键 | 支持 |
| Files | 支持 | 在文件列表区域点击中键 | 支持 |
| One Commander | 支持 | 在文件列表区域点击中键 | 支持 |
| Total Commander | 支持 | 在文件列表区域点击中键 | 支持 |
| XYplorer | 支持 | 在文件列表区域点击中键 | 支持 |

这五款都是通过匹配运行中的进程来识别目标窗口的(其中 Directory Opus 和 Total Commander 还会通过它们各自公开文档记录的 `WM_COPYDATA` 远程控制接口通信，而不是直接抓取界面；Files 和 One Commander
没有提供远程控制协议，因此改用 UI Automation)。

## Directory Opus 的索引文件夹大小

启用 Directory Opus 插件中的**启用 Lertaro 大小列**选项后(默认开启)，Lertaro 会在 Directory Opus 中安装**Lertaro 大小**脚本列。它从 Lertaro 当前内存中的索引显示每个已索引文件夹的递归大小，不会扫描磁盘。文件行仍使用 Directory Opus 原生的大小列；Lertaro 没有索引的文件夹在此列中不会显示值。关闭该选项后，Lertaro 不会再写入或更新脚本；已经安装的脚本会被刻意保留。

在 Directory Opus 的列选择器中添加**Lertaro 大小**。要让它在切换目录和重启 Directory Opus 后持续显示，请依次选择**文件夹 → 文件夹格式 → 保存 → 将格式保存给所有文件夹**。本地磁盘、网络驱动器等更具体的文件夹格式优先于用户默认格式；如有这类格式，也需要把该列加入对应格式。

## 应用程序自带的对话框(可选插件)

这几项针对的是第三方应用程序里的某一个特定对话框——而不是整个应用程序，跟上面内置的那几个对话框是同一个思路。在[设置 → 插件](./settings/plugins)里安装/启用，每个插件只有一个组件，直接在那里开关即可(没有单独的配置对话框，因为也没有别的东西需要切换)。

| 目标 | 内嵌搜索 | 快速导航 | 活动路径检测 |
|---|---|---|---|
| WPS Office 的打开/保存对话框 | 支持 | 中键，或左键点击内嵌窗口自带的图标 | —— |
| WinRAR 的解压对话框 | 支持 | 中键，或左键点击内嵌窗口自带的图标 | —— |
| Bandizip 的解压对话框 | 支持 | 中键，或左键点击内嵌窗口自带的图标 | —— |
| Bandizip 的添加文件对话框 | 支持 | 中键，或左键点击内嵌窗口自带的图标 | —— |

识别靠的是控件结构而不是窗口标题，所以每款软件不管装的是哪种语言包都能正常工作。WPS 那一项覆盖文字、表格、演示和 PDF——它们用的是同一个对话框；WPS 不使用 Windows 自带的对话框，而是自绘了一个，这也正是它需要单独一个插件、而大多数程序被上面内置的那几项覆盖的原因。跟内置的那几个一样，活动路径检测在这里也没有意义——Lertaro 已经嵌入对话框本身了，不存在另一个"其它窗口"可供它检测并作为搜索范围。
