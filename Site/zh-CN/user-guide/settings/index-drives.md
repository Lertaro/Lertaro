# 索引管理

索引设置页面用于精细化控制 Lertaro 针对本地硬盘、网络存储、WSL 子系统以及自定义文件夹的索引范围、刷新策略与排除规则。页面顶部包含五个标签页：**本地驱动器**、**网络驱动器**、**WSL**（检测到发行版时自动显示）、**文件夹**与**排除规则**。

## 1. 本地驱动器（Local Drives）

- **顶部汇总状态**：展示当前已索引的物理驱动器数量与总文件/文件夹条目数，并提供**重建索引**按钮触发所有本地磁盘的全量重建。
- **驱动器列表行**：每个物理分区独立显示一行：
  - **启用/禁用复选框**：独立开关该磁盘的索引。
  - **文件系统与状态**：显示底层文件系统类型（NTFS、ReFS、FAT32、exFAT 等）、当前状态与已索引条目数。
  - **单盘操作**：每行提供独立的**重建**与**移除**操作；在重建扫描进行时会动态提供**停止**按钮。
- **实时监控机制**：NTFS 与 ReFS 卷通过 Windows 系统的 USN 变更日志实现毫秒级增量同步；FAT32 与 exFAT 卷通过文件系统实时变更事件监听。
- **重建不中断**：在某个磁盘重建期间，旧索引将继续响应用户的搜索查询，直到新索引构建完成后一次替换，期间搜索不会中断。若重建过程被系统重启或手动停止中断，下次会自动从断点继续。

## 2. 网络驱动器（Network Drives）

- **网络存储支持**：展示所有已映射的 Windows 网络共享磁盘（SMB / NAS）。
- **刷新模式（Refresh Mode）**：网络存储缺乏本地 USN 日志，因此支持定制计划轮询策略：
  - **手动** —— 仅在点击“重建索引”时重新扫描。
  - **每 15 分钟** —— 高频协同办公目录推荐。
  - **每小时** —— 均衡型定时扫描。
  - **每天** —— 静态归档共享推荐。
- **符号链接环路保护**：扫描引擎内置了分支祖先路径栈与符号链接循环检测算法，即使 NAS 共享中存在指向父级目录的软链接或重解析点，也能自动拦截死循环，确保索引数量准确不膨胀。

## 3. WSL（Linux 子系统）

当且仅当系统检测到至少安装了一个 WSL 发行版时，本标签页会自动出现：

- **自动探测**：自动识别 Ubuntu、Debian、Arch 等已安装的 WSL 发行版。
- **状态与刷新**：提供与网络驱动器完全一致的状态监控与刷新模式配置（手动 / 每 15 分钟 / 每小时 / 每天）。
- **零 I/O 搜索**：搜索 WSL 文件时直接查询内存索引树，完全不唤醒或阻塞 Linux 子系统。

## 4. 文件夹（Folders）

当你不希望索引整个驱动器或整台 NAS 服务器，而只想精准收录特定工作目录时，可以使用自定义文件夹索引：

- **多选添加**：点击**添加文件夹**按钮打开原生选择器，支持按住 `Ctrl` 或 `Shift` 一次性批量选择添加多个目录。
- **UNC 路径支持**：支持直接添加类似 `\\server\share\projects` 的局域网 UNC 共享目录。
- **独立计划刷新**：每个文件夹均拥有独立的启用开关、条目计数与刷新模式下拉框（手动 / 每 15 分钟 / 每小时 / 每天）。

## 5. 排除规则（Exclusions）

排除规则用于过滤搜索结果，并限定网络存储、WSL 与自定义文件夹的走查范围；它不会停止本地磁盘的索引——本地分区始终整盘走查，所以在这里写 `E:\` 只会隐藏它的结果。要停掉某块本地磁盘的索引，请在上方**本地驱动器**标签页里关闭它。规则是一张**统一列表**，没有子标签页：每条规则由匹配方式与档位组成，匹配方式按写法自动判定，输入框实时显示「识别为」。

- **完整路径**：以盘符（`D:\Cache`）、UNC（`\\server\share`）、环境变量（`%ProgramData%`、`%APPDATA%`）或 `shell:` 虚拟路径开头，屏蔽该目录及其全部子项。
- **通配符**：其余写法一律按通配符处理。`*` 匹配单层目录内的任意字符（`*.log`），`?` 匹配单个字符，`**` 跨层级递归（`**\node_modules\**`）。不含分隔符的规则按名称命中任意层级（`node_modules`、`*.tmp`）；含分隔符的规则从盘符根锚定——`Listary\abc` 命中 `C:\Listary\abc` 及其子项，但不会命中 `D:\work\Listary\abc`。
- **正则表达式**：两端用 `/` 包住，对完整路径或文件名做隐式部分匹配，例如 `/^\./` 排除 Linux 式隐藏点文件，`/~\$/` 排除 Office 产生的临时锁定文件。能用通配符就别写正则：正则每次匹配都要解释执行，更费资源。

**档位**决定怎么处理：**排除**完全不显示，**低／正常／高**只影响先后，高优先规则还能勾选置顶，把命中行钉在结果最前。档位有两种写法：行右侧的下拉，或文本前缀 `!` 排除、`-` 低、`+` 高，不写是正常；行首加一个反斜杠可把前缀当普通字符。

> [!NOTE]
> 前缀只在**添加**输入框与**批量编辑**里剥掉。行内编辑已有规则时文本按字面处理，改档位请用下拉：把 `!` 写进通配符规则，它就成了路径里的字面字符，而 Windows 路径不含 `!`，于是这条规则永远命中不了任何东西，页面上也不会报错。

本地盘在搜索时才套用规则；网络盘、WSL 与自定义文件夹在建立索引时就跳过排除项，应用设置后自动刷新。优先级规则被排除规则盖住时，列表上方出现冲突横幅，被盖住的规则不会生效。

> [!TIP]
> 排除规则支持**单条添加**与**批量导入导出**：点击**从列表生成**可将现有规则导出为多行文本，编辑后点击**应用到列表**即可一次性批量生效。批量文本里只要有一行无法识别，整批都不会应用，文本留在框里等你修改。
