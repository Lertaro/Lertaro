# 疑難排解

## 全域熱鍵沒有反應

1. 先看**設定 → 執行狀態**——如果背景服務沒有執行，重新安裝或重新啟動它通常能解決索引相關的問題，但叫出熱鍵本身是由 App 處理程序處理的，不是服務，所以這只是一個次要排查項。
2. 如果目前前景應用程式是以系統管理員身分執行的，而 Lertaro 不是，Windows 會阻止低權限處理程序向它傳送輸入。Lertaro 的背景熱鍵監聽處理程序會在你的帳戶是系統管理員時自動提權——不需要開關，也不會彈出 UAC 視窗。如果熱鍵還是打不到已提權的視窗，先去[**設定 → 執行狀態**](./settings/service-status)確認背景服務在執行，因為提權的監聽處理程序是由它拉起的。如果你的帳戶本身不是系統管理員，這個限制沒有辦法繞過——Windows 不允許低權限處理程序向高權限處理程序傳送輸入。
3. 檢查[處理程序黑名單](./settings/hotkeys-page#process-blacklist)——如果前景應用程式的可執行檔名稱被（有意或無意地）加入了黑名單，Lertaro 的全域熱鍵在它處於前景時會被刻意放行、不做攔截。
4. 如果前景應用程式是真正全螢幕（鋪滿了整個顯示器），Lertaro 預設會自動放行它的熱鍵——為了不和全螢幕遊戲搶鍵盤。如果你設定的組合鍵不會跟全螢幕應用程式自己用到的按鍵衝突，可以在**設定 → 熱鍵 → 顯示/隱藏快速搜尋**旁邊開啟**全螢幕應用程式聚焦時仍然回應**，讓它在全螢幕下也照常生效。不想開這個開關的話，切出全螢幕（Alt+Tab），或者把應用程式改成視窗化/無邊框視窗模式而不是獨佔全螢幕，也能避免這個情況。

## 搜尋結果看起來過時了

NTFS 和 ReFS 磁碟是透過 USN 記錄檔近乎即時更新的；其他本機檔案系統（FAT32、exFAT 等）沒有記錄檔可用，改為直接監看檔案系統變化，同樣是持續即時的。如果還是有內容看起來不對（剛建立的檔案沒出現，或者已刪除的檔案還在），可以到**設定 → 索引 → 本機磁碟機**（或**網路磁碟機**）對相應磁碟執行**重建索引**。

## 網路磁碟機好像一直不重新整理

網路共用沒有本機 NTFS 磁碟區那種可以監看的變更記錄檔，所以是按排程定時重新掃描的。到**設定 → 索引 → 網路磁碟機**檢查該磁碟機的**重新整理模式**——如果是**手動**，就不會自動更新，改成定時重新整理，或者直接點**重建索引**手動重新整理一次。對於 NAS SMB 共享下的特殊軟連結或遞迴路徑，掃描引擎已內建迴圈檢測，避免重複循環。

## 預覽視窗顯示不對/被裁切

理論上不應該發生——Lertaro 會自動把 QuickLook 預覽視窗的位置和大小限制在目前顯示器的可用區域內。如果還是看到裁切，可以先到**設定 → 通用 → 預覽視窗 → 重設預覽視窗設定**排除掉手動設定了異常寬高值的可能，並確認使用的是最新版本。

## 某個檔案/資料夾完全搜不到

- 檢查它是否被排除了——**設定 → 索引 → 排除規則**支援精確路徑、glob 萬用字元和正規表示式三種方式，任何一種都有可能無意中命中它。
- 檢查它所在的磁碟是否在**設定 → 索引 → 本機/網路磁碟機**裡被啟用。

## 在內嵌視窗裡用輸入法打中文（或其他需要候選框的語言）不生效

[內嵌視窗](./getting-started#三種視窗)故意不會從它嵌入的那個視窗手裡搶走真正的鍵盤焦點——這樣你關掉它時才能乾淨俐落地回到剛才的狀態，不會有焦點閃爍。但輸入法的組字過程（候選字清單，以及最終上屏的字元）只會發生在**真正持有焦點**的那個視窗上，而這個視窗始終是被嵌入的目標應用程式，不是 Lertaro——所以沒有任何訊息是 Lertaro 能攔截到、從而擷取你打的內容的。這是內嵌視窗運作方式帶來的結構性限制，不是 bug。

兩個辦法：

- 直接打拼音字母（不需要真的彈出候選框）——Lertaro 會自動按拼音比對中文檔名，見[搜尋語法](./search-syntax#中文檔名-拼音別名)。
- 改用[快速視窗](./getting-started#三種視窗)（預設按兩下 `Ctrl` 叫出）——它是一個真正取得焦點的視窗，輸入法在裡面能正常運作。

## 還是沒解決？

在提交 GitHub issue 之前，先看看 **[設定 → 執行狀態](./settings/service-status)** 裡 **Service**、**App**、**Hook** 三個記錄分頁——搜尋框可以按關鍵字篩選，層級下拉式選單可以按嚴重程度篩選。
