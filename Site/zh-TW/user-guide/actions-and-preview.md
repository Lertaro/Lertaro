# 動作選單與預覽

## 動作選單

每個結果——檔案、資料夾或應用程式——除了「直接開啟」之外還有一整套動作：在檔案總管中定位、複製路徑、以系統管理員身分執行、剪下/複製/貼上檔案本身、刪除(移入資源回收筒)或徹底刪除，以及外掛新增的任何動作(比如完整的 Windows 右鍵選單，包含串接式子選單)。

用**開啟動作選單**熱鍵(預設 `Ctrl+O`)或在選中結果上按方向鍵右鍵即可開啟。選單內：

- **上/下一項**——方向鍵，或你自己設定的[上/下一項熱鍵](./hotkeys)，都可以移動高亮項。哪怕自訂綁定成了裸 `Tab` 鍵這種情況，在這裡也會和主結果清單裡表現完全一致。
- 在帶子選單的項目(比如「傳送到」這類串接式選單)上按**右方向鍵/Enter**會進入子選單；**左方向鍵**
  或(搜尋框為空時的)**Backspace** 會退出一層。
- **Escape** 退出動作選單；如果之前輸入過內容用來篩選動作清單，會先清空搜尋框。
- 輸入文字可以按名稱篩選目前可見的動作，和篩選搜尋結果的方式一樣。

## 完整視窗的結果清單

按兩下一個結果通常就是開啟它，和按 Enter 一樣——只有一個例外：按兩下**路徑**欄會改成開啟該結果所在的資料夾，效果和在這一行其它地方按 `Ctrl`+Enter 一樣。外掛自己的自訂欄也可以給自己定義同樣的按兩下行為。

結果清單會保留每一筆符合項目，而不是截斷成固定的一頁；而且它會隨結果陸續到達逐步填入，不必等到搜尋結束才一次出現——在大容量磁碟上，一個寬泛的查詢可能要跑好幾秒，而這段時間內各列始終可用。方向鍵導覽在兩端循環：在第一列按 ↑ 會跳到最後一列，在最後一列按 ↓ 會回到第一列。

這個視窗沒有標題列，它的頂部區域就是拖曳區：按住其中任何不是搜尋框、也不是視窗按鈕的位置拖動，即可移動視窗。指標位於頂部區域時，頂端會有一條提示條淡入，指示可以從哪裡抓取。

## QuickLook 預覽

在選中結果上按 **QuickLook** 熱鍵(預設 `Alt+P`)會開啟一個停靠在搜尋視窗旁邊的預覽面板——圖片、文件等可預覽的檔案類型不用離開 Lertaro 就能檢視。再按一次(或切換到 QuickLook 無法預覽的結果)
即可關閉。

資料夾預覽最多列出 30 個直接子項目，並顯示對應的檔案或資料夾圖示。即使 Windows 檔案總管已設定為顯示隱藏項目，預覽中仍會篩除隱藏項目和系統項目。

音訊和視訊檔案——只要是 WPF 內建播放能力不需要額外解碼器就能支援的格式(MP4、WMV、AVI、MOV、
MP3、WAV、WMA 等)——一開啟預覽就會自動播放，帶一個跟隨佈景主題的小型播放列(播放/暫停、進度拖曳、目前/總長度、靜音)，而不是顯示靜態縮圖。切換到其他結果或關閉預覽會立刻停止播放。如果某個檔案的具體編碼解不出來，會退回顯示靜態縮圖。

預覽視窗的尺寸是固定的、使用者可設定的——見[設定 → 通用 → 預覽視窗](./settings/general#預覽視窗)——不會隨目前顯示的結果數量變化。不管設定成多大，Lertaro 都會自動保證預覽視窗完整顯示在螢幕內:如果設定的尺寸在目前顯示器上放不下與搜尋視窗並排顯示，會自動貼到有空間的一側；如果設定的尺寸本身就比顯示器可用區域還大，視窗會被縮小到能完整放下，而不會跑到螢幕外面。

如果正在預覽的檔案需要它自己的原生處理程序彈出一個對話方塊——最常見的就是 Word 或 Excel 詢問加密文件的密碼——快速視窗和預覽面板會在這個彈出視窗存續期間自動隱藏，否則它們會擋在彈出視窗前面，讓彈出視窗根本點不到。這不是 Lertaro 當機或關閉了:處理完那個彈出視窗(輸入密碼、關掉它,隨便什麼它要求的操作)之後，兩個視窗會原樣恢復，搜尋內容和選取項目都還在。

預覽視窗的頂部本身就是被預覽檔案的拖曳來源——把它拖到檔案總管、編輯器或任何其他放置目標，效果與把結果列從搜尋視窗拖出去完全一致。

從快速視窗開啟完整視窗時，會把預覽視窗的開啟狀態一併帶過去，所以原本已經開著的預覽會保持開啟。

### 透過 QuickLook 的外部預覽(可選)

雖然名字撞了，但這和上面說的內建預覽面板是兩回事:這裡指的是一個獨立的第三方應用程式，同樣叫
**QuickLook**([GitHub 上的 QL-Win/QuickLook](https://github.com/QL-Win/QuickLook)，GPL 授權)，需要你自己安裝——Lertaro 不會內建它。

如果你裝了它並且它正在執行，內建的(實驗性)**QuickLook 橋接**外掛——和其他外掛一樣，可以在[設定 → 外掛](./settings/plugins)裡看到、開關——會透過它自己的具名管道連上它，把上面提到的所有內建預覽類型的活兒都接管過去，優先權比它們都高。這期間 Lertaro 自己的預覽面板會隱藏起來，
QuickLook 那個獨立的浮動視窗會被挪到本該是預覽面板佔據的那塊地方——看起來就像「預覽面板變成了
QuickLook」，但技術上 QuickLook 的視窗一直是一個完全獨立的最上層視窗，只是被 Lertaro 挪過去跟著走而已。

動作選單裡有一項**用 QuickLook 預覽**，即便某個內建預覽類型本來會贏，也可以用它手動把某個結果送去給 QuickLook 看。

因為這完全依賴 QuickLook 自己那套沒有公開文件、私有的處理程序間通訊協定，而不是什麼正式發布的整合介面，QuickLook 以後的版本隨時可能改掉這套協定，把這個功能悄悄弄壞。解除安裝或關掉 QuickLook
不影響其他任何東西——Lertaro 會自動退回到自己內建的那些預覽類型。
