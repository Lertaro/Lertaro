# 故障排查

## 全局熱鍵沒有反應

1. 先看**設定 → 運行狀態**——如果後臺服務沒有運行，重裝或重啓它通常能解決索引相關的問題，但呼出熱鍵本身是由 App 處理程序處理的，不是服務，所以這只是一個次要排查項。
2. 如果當前前臺應用是以系統管理員身份運行的，而 Lertaro 不是，Windows 會阻止低權限處理程序向它發送輸入。Lertaro 的後臺熱鍵監聽處理程序會在你的帳戶是系統管理員時自動提權——不需要開關，也不會彈 UAC 視窗。如果熱鍵還是打不到已提權的視窗，先去[**設定 → 運行狀態**](./settings/service-status)確認後臺服務在運行，因為提權的監聽處理程序是由它拉起的。如果你的帳戶本身不是系統管理員，這個限制沒有辦法繞過——Windows 不允許低權限處理程序向高權限處理程序發送輸入。
3. 檢查[處理程序黑名單](./settings/hotkeys-page#process-blacklist)——如果前臺應用的可執行檔案名被（有意或無意地）加入了黑名單，Lertaro 的全局熱鍵在它處於前臺時會被刻意放行、不做攔截。
4. 如果前臺應用是真正全屏（鋪滿了整個顯示器），Lertaro 預設會自動放行它的熱鍵——為了不和全屏遊戲搶鍵盤。如果你設定的組合鍵不會跟全屏應用自己用到的按鍵衝突，可以在**設定 → 熱鍵 → 顯示/隱藏快速搜尋**旁邊打開**全屏應用聚焦時仍然響應**，讓它在全屏下也照常生效。不想開這個開關的話，切出全屏（Alt+Tab），或者把應用改成視窗化/無邊框視窗模式而不是獨佔全屏，也能避免這個情況。

## 搜尋結果看起來過時了

NTFS 和 ReFS 磁碟是通過 USN 日誌近乎實時更新的；其他本地檔案系統（FAT32、exFAT 等）沒有日誌可用，改為直接監聽檔案系統變化，同樣是持續實時的。如果還是有內容看起來不對（剛創建的檔案沒出現，或者已刪除的檔案還在），可以到**設定 → 索引 → 本地磁碟機**（或**網絡磁碟機**）對相應磁碟執行**重建索引**。

## 網絡磁碟機好像一直不刷新

網絡共享沒有本地 NTFS 卷那種可以監聽的變更日誌，所以是按計劃定時重新掃描的。到**設定 → 索引 → 網絡磁碟機**檢查該磁碟機的**刷新模式**——如果是**手動**，就不會自動更新，改成定時刷新，或者直接點**重建索引**手動刷新一次。對於 NAS SMB 共享下的特殊符號鏈接或遞歸路徑，掃描引擎已內置環路檢測，避免重複循環。

## 預覽視窗顯示不對/被裁切

理論上不應該發生——Lertaro 會自動把 QuickLook 預覽視窗的位置和大小鉗制在當前顯示器的可用區域內。如果還是看到裁切，可以先到**設定 → 通用 → 預覽視窗 → 重置預覽視窗設定**排除掉手動設定了異常寬高值的可能，並確認使用的是最新版本。

## 某個檔案/資料夾完全搜不到

- 檢查它是否被排除了——**設定 → 索引 → 排除規則**支援精確路徑、glob 通配符和正則表達式三種方式，任何一種都有可能無意中命中它。
- 檢查它所在的磁碟是否在**設定 → 索引 → 本地/網絡磁碟機**裏被啓用。

## 在內聯視窗裏用輸入法打中文（或其他需要候選框的語言）不生效

[內聯視窗](./getting-started#三種視窗)故意不會從它嵌入的那個視窗手裏搶走真正的鍵盤焦點——這樣你關掉它時才能乾淨利落地回到剛才的狀態，不會有焦點閃爍。但輸入法的組合過程（候選詞列表，以及最終上屏的字元）只會發生在**真正持有焦點**的那個視窗上，而這個視窗始終是被嵌入的目標應用，不是 Lertaro——所以沒有任何消息是 Lertaro 能攔截到、從而捕獲你打的內容的。這是內聯視窗工作方式帶來的結構性限制，不是 bug。

兩個辦法：

- 直接打拼音字母（不需要真的彈出候選框）——Lertaro 會自動按拼音匹配中文檔案名，見[搜尋語法](./search-syntax#中文檔案名-拼音別名)。
- 改用[快速視窗](./getting-started#三種視窗)（預設雙擊 `Ctrl` 呼出）——它是一個真正獲得焦點的視窗，輸入法在裏面能正常工作。

## 還是沒解決？

在提交 GitHub issue 之前，先看看 **[設定 → 運行狀態](./settings/service-status)** 裏 **Service**、**App**、**Hook** 三個日誌 Tab——搜尋框可以按關鍵詞過濾，等級下拉式方塊可以按嚴重程度過濾。
