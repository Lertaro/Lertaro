# 搜尋語法

Lertaro 的搜尋列遠不止支援簡單的純文字搜尋。它配備極速的比對演算法，支援模糊跳躍比對、布林邏輯、排除、磁碟機與路徑範圍限定、排序與篩選查詢標記，以及多語言別名。所有語法都可以在同一條查詢中自由混用。

## 1. 基礎比對與大小寫

### 模糊比對（預設）

Lertaro 預設啟用模糊比對（Fuzzy Matching）。只要按順序輸入任意字元，即使這些字元散落在檔案或資料夾名稱各處，也能成功比對：

| 輸入範例 | 比對結果 | 說明 |
| :--- | :--- | :--- |
| `ltro` | `Lertaro.exe` | 字元依序比對：`l` → `t` → `r` → `o`（**L**er**t**a**ro**.exe） |
| `vsc` | `Visual Studio Code.lnk` | 比對每個單詞的首字母（**V**isual **S**tudio **C**ode） |
| `rt-fin` | `Q3-report-final.docx` | 比對連續子字串（Q3-repo**rt-fin**al.docx） |

在**設定 → 一般 → 系統 → 啟用模糊比對**中關閉此選項後，每個普通詞都必須是連續子字串——`abc` 只會比對名稱中含連續 `abc` 的項目，不再比對 `a-b-c`。此開關只影響普通詞：排除詞一律以精確比對處理（見下文）；下文介紹的標記語法無論如何都不受影響，而單一詞仍可用前導 `?` 翻轉到相反的一側（見第 3 節）。

### 大小寫不敏感

比對一律忽略大小寫，且雙向皆然——你輸入的大小寫永遠不改變比對結果，檔案名稱的大小寫也不會。`myfile`、`MyFile` 與 `MYFILE` 彼此都能互相比對。

沒有大小寫敏感模式：輸入大寫字母永遠不會把某個詞收窄為僅比對大小寫完全相符的結果。

### 拼音別名與排序

中文名稱可用拼音搜尋，共有兩種形式：**簡拼**（每個字一個字母——「惡性」為 `ex`）與**全拼**（完整拼出每個音節——「證書」為 `zhengshu`）。

**排序權重：比對位置 > 覆蓋率 > 英文 > 簡拼 > 全拼。** 比對起點越靠左者優先；其次是更緊湊、更完整的比對；英文/簡拼/全拼只在前兩者都已相同時才用於區分結果。因此英文比對不再自動優先於拼音比對——只有當兩者位置與緊湊度都相同時才會優先。最後一個音節只輸入一半仍然可比對，所以當你還在輸入時，`zhengsh` 依然能找到「證書」。

**關閉模糊比對時**，拼音比對必須對齊詞首。`ex` 能找到「惡性」（兩個字的簡拼），但找不到「學習」（那必須把 `xue` 的結尾接到 `xi` 的開頭）。開啟模糊比對時，這種寬鬆的讀法正是你所要求的，依然可用。

## 2. 多詞組合與布林邏輯

### 空格：AND

以空格分隔多個搜尋詞，表示要求所有條件都成立。詞在檔案名稱中出現的順序**無所謂**：

```text
report final 2024
```

上述查詢同時比對 `2024-Q3-report-final.docx` 與 `final_report_2024.pdf`。

### 豎線 `|`：OR

使用豎線符號 `|` 分隔多個詞，只要符合其中任一選項即可：

```text
png | jpg | gif
```

你可以自由組合 AND 與 OR 邏輯：

```text
report | summary
```

這會找出符合 `report` 或 `summary` 的檔案。在 OR 查詢中，所有命中分支的比對詞都會在結果名稱中同步反白顯示。

### 運算子優先順序：AND 的結合比 OR 更緊密

當空格（AND）與豎線 `|`（OR）混用在同一條查詢中時，預設上空格比豎線結合得**更緊密**：每一段以空格分隔的詞會先被 AND 成各自的群組，這些群組再彼此 OR 起來。不支援括號，而這正是標準的布林讀法——但舊的結合順序只差一個開關就能恢復（見下）。

```text
report | summary 2024 | draft
```

等價於 `report OR (summary AND 2024) OR draft`。

這正是先輸入幾個候選項、再對其中一個加上限定的用家所預期的讀法：`summary 2024` 會保持為單一合取條件，而不會散開成兩個彼此獨立的候選項。

#### 切回 OR 優先

在 **設定 → 一般 → 系統 → OR 優先於 AND（舊行為）** 下，你可以恢復 Lertaro 歷史上的結合順序，也就是豎線比空格結合得更緊密：

```text
report | summary 2024 | draft
```

此時代表 `(report OR summary) AND (2024 OR draft)`。

此開關只改變兩個運算子之間的優先順序——不會引入任何新運算子，而且對只使用其中一個運算子的查詢沒有任何影響（無論此設定為何，`read me` 與 `readme | rdm` 的意義都相同）。

注意：`|` 必須是兩側都有空格的獨立標記——`a|b` 或 `a |b` 不會被解析為 OR。這同樣適用於排除詞：`b | :c` 會被讀成「b，或非 c」，因此若要從整條查詢中排除某個詞，請讓該排除詞擁有自己獨立的空格位置（`b :c`）。

#### 優先順序不受引號影響

沒有任何引號語法能改變優先順序的讀法；分組方式完全由上面的設定決定。只有當 `|` 是兩側帶空格的獨立標記時它才是 OR，所以把它寫進普通文字（如 `data|backup`）只會搜尋這個字面字串。

### 空格規則

沒有辦法把空格放進單獨一個詞裡。空格永遠是 AND 分隔符，因此帶空格的查詢永遠是若干個 AND 詞——這是 Lertaro 唯一一處會把標點讀作結構的地方：

```text
final report
```

是 `final` AND `report`，與把它們當作一個短語 `final report` 並不相同。

**引號和反斜線都解決不了這個問題。** `'final report'` 和 `"final report"` 不是短語語法：引號會作為字面字元參與比對，所以這類查詢是在找名稱裡含有引號的檔案，結果只會是空。`final\ report` 同樣會被讀成 `final` AND `report` 兩個詞。

結論是 Lertaro 沒有精確短語搜尋。當這兩個詞在你想找的名稱裡相鄰時，搜更有辨識度的那一半、讓排序把它頂到前面即可——或者使用正規表達式子句，它會把名稱當作一個整體來比對（見下文）：

```text
/^final report/
```

### 貼上多行文字自動摺疊為 OR

當你複製多行文字（例如試算表、文字檔或記錄檔中的檔案名稱）並直接貼到搜尋列時，Lertaro 會自動把各行摺疊成一條以 `|` 分隔的 OR 查詢（空行會自動略過）：

```text
123
456
678
```

貼上後會自動變成：

```text
123 | 456 | 678
```

## 3. 搜尋運算子速查表

### 運算子表

| 運算子 / 語法 | 類型 | 說明 | 輸入範例 |
| :--- | :--- | :--- | :--- |
| *(無)* | 預設詞 | 開啟模糊比對時為模糊，關閉時為精確子字串 | `report` |
| `:` | 排除 | 丟棄名稱中含此文字的所有結果（一律精確，永不模糊） | `:temp` |
| `?` | 精確性反轉 | 將該詞在模糊與精確之間翻轉，即取目前設定的相反值 | `?report` |
| `\|` | OR 邏輯 | 比對豎線的任一側 | `doc \| pdf` |
| `/.../` | 正規表達式 | 以 .NET 正規表達式比對名稱（見下文） | `/^report.*\.md$/` |
| `*` | 繞過排除 | 一次性略過你所設定的排除規則（僅限第一個字元） | `*node_modules` |
| `<` `>` | 排序 / 篩選標記 | 排序並可選擇性篩選結果（見[第 5 節](#_5-查詢標記-排序與篩選)） | `<s>20m` |
| `\` | 外掛模組標記 | 套用外掛模組提供的篩選器，例如檔案分類（見[第 5 節](#_5-查詢標記-排序與篩選)） | `\audio` |

### 運算子詳細行為與組合

1. **排除 `:`**——`:term` 會丟棄名稱中含 `term` 的所有結果。排除寫在冒號之後且**不加空格**（`:temp`，而非 `: temp`），而且它不能是查詢中唯一的內容：由於排除只能移除結果，一條只有排除詞的查詢會完全不顯示任何結果。實務上這代表永遠要保留至少一個普通詞與它並存。
2. **排除一律精確**——即使模糊比對開啟，排除詞也以連續子字串比對，而且不會透過拼音別名擴展。否則鬆散的子序列或拼音拼法會移除你根本沒指名的檔案。
3. **單獨的冒號會被忽略**——後面什麼都沒有的 `:` 不是運算子；它只會從查詢中直接被丟棄。
4. **磁碟機冒號不一樣**——磁碟機代號跟在冒號後面（`d:`，見[第 4 節](#_4-路徑模式與磁碟機範圍限定)），而排除詞則在冒號前面（`:temp`）。兩者永遠不會混淆，而詞內部的冒號（`c:\path`）只是普通文字。
5. **正規表達式子句會在讀取查詢的其他任何環節之前先被抽離**——這正是讓它的反斜線與斜線不會被誤認為路徑的原因，也代表子句可以位於查詢中的任何位置（`/\.md$/ report` 與 `report /\.md$/` 是同一筆搜尋）。
6. **精確性反轉 `?`**——`?term` 取模糊比對設定的**相反**值：開啟模糊比對時該詞變成連續子字串，關閉時變成鬆散子序列。這是在同一條查詢裡混用兩種讀法的唯一方式——`?report draft` 要求 `report` 連續出現，而 `draft` 可以分散。此引導符只從**詞的第一個字元**讀取，因此 `rep?ort` 是字面文字 `rep?ort`（檔名中不可能出現該字元，所以它比對不到任何東西），而且只作用於它所屬的那個詞。與單獨的 `:` 一樣，單獨的 `?` 會被丟棄。冒號會先被讀取，所以 `:?temp` 排除的是字面文字 `?temp`。

**運算子組合範例**：

- `report :draft`：找出名稱含 `report` 的項目，並丟棄名稱中含 `draft` 的項目。
- `IMG :png :gif`：找出名稱含 `IMG` 的項目，同時丟棄 `png` 與 `gif` 檔案。兩個排除詞以 AND 結合——只有兩者都不含的名稱才能留下。
- `log :temp :bak`：保留既不是暫存檔也不是備份檔的 `log` 檔案。

### 正規表達式（`/.../`）

在兩條斜線之間寫一段 .NET 正規表達式，即可精確比對檔案**名稱**：

```text
/^report.*\.md$/
```

這會找出以 `report` 開頭、以 `.md` 結尾的名稱。子句會與查詢其餘部分以 AND 結合，因此 `report /\.pdf$/` 只會保留 `report` 命中結果中的 PDF。

有四件事值得了解：

- **它比對的是名稱，不是路徑**，也不是檔案內容。若要針對資料夾，請使用路徑查詢。
- **它不會經過拼音別名。** 正規表達式描述的是名稱中實際出現的字元，因此中文名稱是以其本身的字元比對，而不是以拼音拼法比對。
- **斜線是分隔符號，而 `\` 用於轉義。** 字面的點號請寫成 `\.`（單獨的 `.` 代表任意字元）。若要比對字面的斜線，請寫成 `\/`。由於 `/` 同時是 Windows 的備用路徑分隔符號，子句必須是一個以 `/` 開頭並以 `/` 結尾的完整詞，而且體內未轉義的 `/` 會提前閉合子句——這正是 `C:/Users/me`、`/mnt/c/Users`、`/usr/local/` 這類前斜線路徑仍按普通路徑處理、不會被當成正規表示式的原因。未閉合的子句會被當作普通文字，而不會吞掉查詢其餘部分。
- **正規表達式無法像普通詞那樣被加速**，因為它不是固定字串。Lertaro 會抽出運算式所要求的最長連續字面字元——`/\.exe$/` 抽出 `.exe`，`/^(ogg|mp3)$/` 則什麼都抽不出來——並用它來在真正執行運算式之前跳過大多數候選項。在這種不含字面字元的正規表達式旁加上一個普通詞，是讓這類搜尋保持快速的可靠方法。

## 4. 路徑模式與磁碟機範圍限定

### 指定磁碟機

在查詢開頭輸入磁碟機代號加上冒號，即可把結果嚴格限定在該磁碟機：

```text
d: report
```

磁碟機規格必須是**獨立的兩個字元標記**：冒號後面必須接空格。`d:report` 不再是磁碟機規格——它是一個搜尋字面文字 `d:report` 的普通詞，因為從開頭兩個字元猜測磁碟機會產生誤判。只有 ASCII 字母會被辨識，所以 `中: x` 也不是磁碟機。

### 完整路徑模式

當查詢內容含路徑分隔符號（`\` 或 `/`）時，Lertaro 會自動切換到完整路徑比對模式：

```text
D:\Projects\Lertaro
```

以路徑分隔符號結尾（例如 `D:\Projects\`）則會搜尋該資料夾**內部**的直接內容。

### 跳轉資料夾

當整條查詢正好是一個存在的資料夾的完整路徑時，完整路徑模式結果的上方會出現一個開啟該資料夾的結果列，按 Enter 即可跳轉：

```text
D:\Projects\Lertaro
D:/Projects/
%LOCALAPPDATA%\abc/d/e
shell:Downloads\Tools
\\server\share\docs
"C:\Users\me\My Documents"
```

以下寫法都有效，而且可以混合使用：分隔符號用 `/` 或 `\`、結尾有無分隔符號皆可、路徑中包含 `%變數%`、`shell:` / `::{CLSID}` 虛擬資料夾、網路共用，或將整體用引號包住。判斷依據是該資料夾是否真的存在：`Core\SearchIndex` 這類的相對路徑不會提供跳轉，尚未存在的資料夾也不會——這兩種情況下只會照常回傳完整路徑模式的結果。

> [!NOTE]
> 外掛模組標記也以 `\` 開頭（例如 `\audio`）。標記會在決定是否進入路徑模式之前先被抽離查詢，因此一條只含標記與普通詞的查詢（`report \audio`）仍然是普通的名稱搜尋。只有在剩餘文字中還留有分隔符號時，才會觸發路徑模式。 以兩個分隔符號開頭的查詢（`\\server\share`）會被讀成 UNC 路徑，因此保留為查詢文字。

### 資料夾比對回退機制

當僅以檔案名稱搜尋無法填滿結果容量時，Lertaro 會自動使用未在檔案名稱中比對到的查詢詞去比對上層資料夾名稱，無需特殊語法：

```text
d01j dcj
```

即使 `dcj` 從未出現在檔案本身的名稱中，Lertaro 也能找到位於名為（或別名為）`dcj` 的資料夾中的 `d01j.txt`。

> [!NOTE]
> 這需要至少有一個詞比對到檔案名稱本身，而且只有在僅比對名稱的結果尚未填滿結果時才會觸發。回退結果一律排在直接比對檔案名稱的結果之後。

## 5. 查詢標記：排序與篩選

查詢標記是以無法出現在 Windows 檔案名稱中的字元開頭的詞，因此永遠不會與你想搜尋的文字混淆。共有兩個家族：

| 家族 | 觸發字元 | 範例 | 擁有者 |
| :--- | :--- | :--- | :--- |
| 排序 / 篩選 | `<` 與 `>` | `<s>20m` | `CoreExtensions` 外掛模組 |
| 外掛模組標記 | 你設定的**外掛模組查詢標記前綴**（預設 `\`） | `\audio` | 認領該標記的外掛模組 |

### 標記可以出現在查詢中的任何位置

標記**不必**放在結尾。下列寫法都等價：

```text
report <s>20m \audio
<s>20m report \audio
\audio report <s>20m
```

只有當標記是**完整單詞**且位於單詞開頭時才算數——`abc\def` 是普通文字，不是標記。

### 排序與閾值（`<` 與 `>`）

第一個字元決定排序方向，接下來的字母決定屬性：

| 標記 | 意義 |
| :--- | :--- |
| `<s` | 依大小排序，最小在前 |
| `>s` | 依大小排序，最大在前 |
| `<c` / `>c` | 依建立時間排序，最舊 / 最新在前 |
| `<m` / `>m` | 依修改時間排序，最舊 / 最新在前 |
| `<a` / `>a` | 依存取時間排序，最舊 / 最新在前 |
| `<f` / `>f` | 資料夾在前 / 檔案在前 |

再加上第二個觸發字元與一個閾值，即可只保留其中一側：

| 標記 | 意義 |
| :--- | :--- |
| `<s>20m` | 大於 20 MB 的檔案 |
| `<s<20m` | 小於 20 MB 的檔案 |
| `>c>2008.8.3` | 建立時間晚於 2008-08-03 的項目 |

第二個觸發字元是**比較**，不是重複排序箭頭：`>` 一律代表下界，`<` 一律代表上界。

大小接受 `k`、`m`、`g` 與 `t` 後綴（二進位單位，所以 `1m` 是 1 MiB），或直接使用位元組數。資料夾/檔案鍵的閾值使用 `f` / `folder` / `dir`。

日期必須**年份在前**。可接受的形式如下（兩位數年份會讀作 `20xx`）：

| 分隔符號 | 年份位數 | 月/日位數 | 範例 |
| :--- | :--- | :--- | :--- |
| `-` | 4 或 2 | 補零或不補零 | `2003-01-03`, `2003-1-3`, `03-1-3` |
| `.` | 4 或 2 | 補零或不補零 | `2003.01.03`, `2003.1.3`, `03.1.3` |
| `/` | 4 或 2 | 補零或不補零 | `2003/01/03`, `2003/1/3`, `03/1/3` |
| 無 | 4 | — | `20030103` |

分隔符號不得混用（`2003-08.03` 不是日期），也不接受月在前面的讀法 `01-03-2003`——順序一律是年、月、日，因此同一條查詢在兩台機器上永遠不會代表兩個不同的日期。僅有年份（`2008`）與年加月（`2008.8`）的形式也同樣接受，分別代表「2008 年期間」與「2008 年 8 月期間」。

### 外掛模組標記（`\`）

外掛模組標記由外掛模組提供，每個標記的意義由外掛模組自行決定。內建的 `CoreExtensions` 外掛模組提供檔案分類篩選器：

- `\doc`：文件（`*.doc; *.docx; *.pdf; *.txt; *.ppt; *.pptx; *.xls; *.xlsx; *.csv; *.rtf; *.md; *.wps`）
- `\img`：圖片（`*.jpg; *.jpeg; *.png; *.gif; *.bmp; *.webp; *.ico; *.svg; *.tif; *.tiff; *.psd; *.ai`）
- `\video`：影片（`*.mp4; *.mkv; *.avi; *.mov; *.wmv; *.flv; *.m4v; *.webm; *.3gp; *.rmvb; *.ts`）
- `\audio`：音訊（`*.mp3; *.wav; *.flac; *.aac; *.ogg; *.m4a; *.wma; *.ape`）
- `\zip`：壓縮檔（`*.zip; *.rar; *.7z; *.tar; *.gz; *.bz2; *.xz; *.iso; *.wim; *.esd`）

**範例**：

- `financial \doc`：在文件中搜尋「financial」。
- `wallpaper \img`：在圖片中搜尋「wallpaper」。

你可以重新命名分類、變更每個分類涵蓋的副檔名，或在 **設定 → 外掛模組 → CoreExtensions** 下新增自己的分類。關鍵字本身以最長優先的方式比對，因此 `\a` 規則與 `\audio` 規則可以並存，且 `\audio` 仍然勝出。

前綴字元可在 **設定 → 一般 → 系統 → 外掛模組查詢標記前綴** 下設定。它不能為空、不能是搜尋語法已占用的字元（`\` `<` `>` `:` `*` `/` `?`）。

完整搜尋視窗左側的類型篩選側邊欄是在同一個外掛模組的**搜尋篩選器**群組中單獨設定的。側邊欄篩選器名稱僅供顯示；前綴引用只會在側邊欄篩選規則內部解析，並指向**自訂篩選器**清單中的關鍵字，包含已停用的自訂篩選器。

### 鏈式標記

由於標記是彼此獨立的詞，一條查詢中可以出現多個標記，每個都會依序生效：

- `report \doc >m`：搜尋「report」，只保留文件，並依修改時間排序（最新在前）。
- `backup \zip <s`：搜尋「backup」，只保留 `.zip` 壓縮檔，並依大小排序（最小在前）。
- `icon \img <s>1m`：搜尋「icon」，只保留大於 1 MB 的圖片，最小在前。

## 6. 特殊搜尋功能

### 單次搜尋繞過排除規則

在查詢開頭加上 `*`，即可在此次搜尋中暫時繞過[**排除規則**](./settings/index-drives#_5-排除規則-exclusions)裡使用者設定的路徑排除、glob 與正規表達式，而無需修改設定：

```text
*node_modules
```

前導的 `*` 會在比對前被剝離。這只會召回已建立索引的檔案（網路/WSL 磁碟機上從未建立索引的排除路徑不會出現）；系統/隱藏檔案篩選器仍然有效。請注意，這裡說的是應用程式自身的排除**規則**，與查詢中的 `:` 排除詞是不同的東西。

### 結果類型觸發符

在 **設定 → 一般 → 快速搜尋視窗 → 結果類型優先順序** 下，你可以為特定結果類型（應用程式、系統設定、檔案分類、外掛模組、檔案等）設定單一字元的**觸發符**。

在快速搜尋視窗中把觸發符輸入為最前面的第一個字元，就只會顯示該結果類型，並隱藏其他所有類型：

```text
;vs
```

若 `;` 被指派給「應用程式」，上述查詢就只會在應用程式中搜尋 Visual Studio。觸發符必須是第一個字元，前面不能有任何內容，而且只適用於快速搜尋與內嵌搜尋視窗。在兩者中，無論觸發符為何，記錄與我的最愛都固定置頂顯示。

> [!NOTE]
> 觸發符必須是查詢的第一個字元——在它前面放外掛模組標記或排序標記（`\img ;vs`）會讓觸發符不被讀取，因為查詢已經不再以它開頭。

## 7. 多語言別名

### 中文檔案名稱：拼音別名

內建 `PinyinAlias` 外掛模組，中文檔案名稱開箱即可用拼音搜尋，零設定：

- **全拼**：輸入 `chongqing` 可比對 `重庆.docx`。
- **拼音簡拼**：輸入 `cq` 也能比對 `重庆.docx`；輸入 `wzry` 可比對 `王者荣耀.exe`。
- **多音字**：常見讀音會自動建立索引（例如 `重庆` 同時可比對 `chongqing` 與 `zhongqing`）。

你可以在 **設定 → 外掛模組** 下確認 `PinyinAlias` 是否處於啟用狀態。

### 西班牙語檔案名稱：重音別名

內建 `SpanishAlias` 外掛模組，含有西班牙語重音字元（`á`、`é`、`í`、`ó`、`ú`、`ü`、`ñ`）的檔案名稱可以用無重音的 ASCII 字母順暢搜尋：

- 輸入 `cancion` 可比對 `Canción.mp3`。
- 輸入 `nino` 可比對 `Niño.txt`。
- 輸入 `ciguena` 可比對 `Cigüeña.png`。

比對到的字元（包含原名稱中的重音母音）都會準確反白。可在 **設定 → 外掛模組** 下管理此外掛模組。

## 8. 常見問題與我的最愛

### 我的最愛，而不是自訂別名

Lertaro 不提供通用的「自訂搜尋別名/巨集」機制。最接近的原生方案有：

- [**我的最愛**](./settings/favorites)：以自訂顯示名稱釘住任何檔案、資料夾或 URL，使其可用該自訂標題搜尋（結果中以 ★ 圖示標示）。
- **檔案篩選器**（見[**即時答案**](./instant-answers#_5-檔案篩選器)）：把觸發關鍵字綁定到指定的資料夾，之後在快速搜尋視窗輸入 `keyword term` 即可把一般索引搜尋限定在那些資料夾。

如果你想以自訂關鍵字觸發自訂指令碼或啟動程式，請參閱[**自訂命令**](./instant-answers#_6-自訂命令)。
