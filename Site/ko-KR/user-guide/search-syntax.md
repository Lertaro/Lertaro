# 검색 문법

Lertaro의 검색창은 단순한 일반 텍스트 검색을 훨씬 뛰어넘는 기능을 제공합니다. 초고속 매칭 알고리즘을 갖추어 퍼지 도약 매칭, 불리언 논리, 제외, 드라이브 및 경로 범위 지정, 정렬 및 필터링 쿼리 토큰, 다국어 별칭을 지원합니다. 모든 문법은 하나의 검색어 안에서 자유롭게 조합할 수 있습니다.

## 1. 기본 매칭 및 대소문자

### 퍼지 매칭(기본값)

Lertaro는 기본적으로 퍼지 매칭(Fuzzy Matching)을 활성화합니다. 원하는 문자를 순서대로 입력하기만 하면 그 문자들이 파일 또는 폴더 이름에 흩어져 있어도 매칭됩니다:

| 입력 예시 | 매칭 결과 | 설명 |
| :--- | :--- | :--- |
| `ltro` | `Lertaro.exe` | 문자가 순서대로 매칭됩니다: `l` → `t` → `r` → `o` (**L**er**t**a**ro**.exe) |
| `vsc` | `Visual Studio Code.lnk` | 각 단어의 첫 글자를 매칭합니다 (**V**isual **S**tudio **C**ode) |
| `rt-fin` | `Q3-report-final.docx` | 연속된 부분 문자열을 매칭합니다 (Q3-repo**rt-fin**al.docx) |

**설정 → 일반 → 시스템 → 퍼지 매칭 활성화**에서 이 기능을 끄면 모든 일반 검색어가 연속된 부분 문자열을 요구하게 됩니다. 즉 `abc`는 연속된 `abc`를 포함하는 이름에만 매칭되고 더 이상 `a-b-c`에 매칭되지 않습니다. 이 토글은 일반 검색어와 제외에만 영향을 주며, 아래에서 설명하는 토큰 문법은 어느 쪽이든 영향을 받지 않습니다.

### 대소문자 무시

매칭은 항상 대소문자를 무시하며 양방향으로 적용됩니다. 입력한 문자의 대소문자는 매칭 대상을 바꾸지 않고, 파일 이름의 대소문자도 마찬가지입니다. `myfile`, `MyFile`, `MYFILE`은 모두 서로 매칭됩니다.

대소문자를 구분하는 모드는 없습니다. 대문자를 입력해도 검색어가 대소문자까지 정확히 일치하는 항목으로 좁혀지지 않습니다.

### 병음 별칭 및 순위

중국어 이름은 두 가지 형태의 병음으로 검색할 수 있습니다. **첫 글자**(글자마다 한 글자 — 恶性이면 `ex`)와 **전체 읽기**(모든 음절을 그대로 표기 — 证书이면 `zhengshu`)입니다.

**순위: 매칭 위치 > 커버리지 > 영문 > 첫 글자 > 전체 병음.** 더 왼쪽에서 시작하는 매칭이 먼저 이기고, 다음으로 더 촘촘하고 완전한 매칭이 이깁니다. 영문/첫 글자/전체 병음은 이 두 기준에서 이미 같은 결과들만 가릅니다. 따라서 영문 매칭이 병음 매칭보다 자동으로 앞서지는 않으며, 둘의 위치와 밀집도가 같을 때만 앞섭니다. 마지막 음절이 일부만 입력되어도 매칭되므로 `zhengsh`는 입력 중에도 계속 证书을 찾아냅니다.

**퍼지 매칭을 끄면** 병음 매칭은 단어 시작 위치에 맞춰져야 합니다. `ex`는 恶性(두 글자의 첫 글자)을 찾지만 学习은 찾지 못합니다(`xue`의 끝을 `xi`의 시작에 이어 붙여야 하기 때문입니다). 퍼지 매칭을 켜면 그러한 느슨한 해석이 바로 요청한 동작이며 그대로 사용할 수 있습니다.

## 2. 다중 검색어 및 불리언 논리

### 공백: AND

여러 검색어를 공백으로 구분하면 모든 조건이 충족되어야 합니다. 파일 이름에서 검색어가 나타나는 순서는 **상관없습니다**:

```text
report final 2024
```

위 검색어는 `2024-Q3-report-final.docx`와 `final_report_2024.pdf` 모두에 매칭됩니다.

### 파이프 `|`: OR

파이프 기호 `|`로 검색어를 구분하면 어느 한쪽만 매칭되어도 충분합니다:

```text
png | jpg | gif
```

AND와 OR 논리를 자유롭게 조합할 수 있습니다:

```text
report | summary
```

이 검색어는 `report` 또는 `summary`에 매칭되는 파일을 찾습니다. OR 검색어에서는 일치한 분기의 모든 검색어가 결과 이름에서 동시에 강조 표시됩니다.

### 연산자 우선순위: AND가 OR보다 강하게 결합

하나의 검색어에 공백(AND)과 파이프 `|`(OR)가 섞여 있으면 기본적으로 공백이 파이프보다 **강하게** 결합합니다. 공백으로 구분된 연속된 검색어가 먼저 각각의 AND 그룹으로 묶이고, 그 그룹들이 다시 OR로 결합됩니다. 괄호는 지원되지 않으며 이것이 표준적인 불리언 해석이지만, 예전 결합 순서도 토글 하나로 되돌릴 수 있습니다(아래 참조).

```text
report | summary 2024 | draft
```

는 `report OR (summary AND 2024) OR draft`와 동일합니다.

이는 몇 가지 대안을 입력한 뒤 그중 하나를 좁히려는 사용자가 기대하는 해석입니다. `summary 2024`는 두 개의 독립된 대안으로 흩어지지 않고 하나의 결합으로 유지됩니다.

#### OR 우선으로 되돌리기

**설정 → 일반 → 시스템 → OR이 AND보다 강하게 결합(레거시)** 에서 파이프가 공백보다 강하게 결합하는 Lertaro의 예전 결합 순서를 복원할 수 있습니다:

```text
report | summary 2024 | draft
```

는 `(report OR summary) AND (2024 OR draft)`를 의미합니다.

이 토글은 두 연산자 사이의 우선순위만 바꾸며 새로운 연산자를 도입하지 않고, 둘 중 하나만 사용하는 검색어에는 영향을 주지 않습니다(어느 설정에서든 `read me`와 `readme | rdm`은 같은 의미입니다).

참고: `|`는 양쪽에 공백이 있는 독립된 토큰이어야 하며, `a|b`나 `a |b`는 OR로 해석되지 않습니다. 이는 제외에도 적용됩니다. `b | :c`는 "b, 또는 c가 아님"으로 해석되므로, 검색어 전체에서 무언가를 제외하려면 제외 항목을 공백으로 구분된 독립된 위치에 두어야 합니다(`b :c`).

#### 우선순위는 따옴표의 영향을 받지 않습니다

우선순위를 읽는 방식을 바꾸는 따옴표 문법은 없습니다. 그룹화는 위의 설정만으로 결정됩니다. `|`가 OR가 되는 것은 양쪽에 공백이 있는 독립된 토큰일 때뿐이므로, `data|backup`처럼 일반 텍스트 안에 넣으면 그 문자열 자체를 검색할 뿐입니다.

### 공백 규칙

하나의 검색어 안에 공백을 넣는 방법은 없습니다. 공백은 항상 AND 구분자이므로, 공백이 있는 쿼리는 항상 여러 개의 AND 검색어가 됩니다. Lertaro가 문장부호를 구조로 읽는 곳은 여기뿐입니다:

```text
final report
```

이는 `final` AND `report`이며, 하나의 구문 `final report`와는 다릅니다.

**따옴표로도 백슬래시로도 해결되지 않습니다.** `'final report'`와 `"final report"`는 구문 문법이 아닙니다. 따옴표는 리터럴 문자로 대조되므로, 이런 쿼리는 이름에 따옴표가 들어 있는 파일을 찾게 되어 결과가 비어 있습니다. `final\ report`도 마찬가지로 `final` AND `report` 두 단어로 읽힙니다.

결론적으로 Lertaro에는 완전 일치 구문 검색이 없습니다. 원하는 이름에서 두 단어가 서로 붙어 있다면 더 특징적인 단어만 검색하고 정렬이 그것을 위로 올리도록 두거나, 이름을 하나의 덩어리로 대조하는 정규식 절을 사용하세요(아래 참조):

```text
/^final report/
```

### 여러 줄 붙여넣기를 OR로 결합

스프레드시트, 텍스트 파일, 로그 등에서 여러 줄의 텍스트(예: 파일 이름 목록)를 복사해 검색창에 바로 붙여넣으면, Lertaro가 각 줄을 `|`로 구분된 하나의 OR 검색어로 자동 결합합니다(빈 줄은 자동으로 건너뜁니다):

```text
123
456
678
```

붙여넣으면 다음과 같이 자동 변환됩니다:

```text
123 | 456 | 678
```

## 3. 검색 연산자 요약표

### 연산자 표

| 연산자 / 문법 | 유형 | 설명 | 입력 예시 |
| :--- | :--- | :--- | :--- |
| *(없음)* | 기본 검색어 | 퍼지 매칭이 켜져 있으면 퍼지, 꺼져 있으면 정확한 부분 문자열 | `report` |
| `:` | 제외 | 이름에 이 텍스트가 포함된 모든 결과를 제거합니다(항상 정확, 퍼지 아님) | `:temp` |
| `\|` | OR 논리 | 파이프의 양쪽 중 하나에 매칭됩니다 | `doc \| pdf` |
| `/.../` | 정규식 | .NET 정규식으로 이름을 매칭합니다(아래 참조) | `/^report.*\.md$/` |
| `*` | 제외 규칙 무시 | 설정된 제외 규칙을 이번 한 번만 무시합니다(첫 번째 문자만) | `*node_modules` |
| `<` `>` | 정렬 / 필터 토큰 | 결과를 정렬하고 선택적으로 필터링합니다([5장](#_5-쿼리-토큰-정렬-및-필터링) 참조) | `<s>20m` |
| `\` | 플러그인 토큰 | 플러그인이 제공하는 필터(예: 파일 카테고리)를 적용합니다([5장](#_5-쿼리-토큰-정렬-및-필터링) 참조) | `\audio` |

### 연산자 상세 동작 및 조합

1. **제외 `:`** — `:term`은 이름에 `term`이 포함된 모든 결과를 제거합니다. 제외는 콜론 뒤에 **공백 없이** 작성하며(`:temp`, `: temp` 아님), 검색어에서 유일한 요소가 되어서는 안 됩니다. 제외는 결과를 제거만 할 수 있으므로 제외만으로 이루어진 검색어는 아무 결과도 표시하지 않습니다. 따라서 실제로는 항상 일반 검색어를 최소 하나 함께 두어야 합니다.
2. **제외는 항상 정확 매칭입니다** — 퍼지 매칭이 켜져 있어도 연속된 부분 문자열로 매칭되며 병음 별칭으로 확장되지 않습니다. 그렇지 않으면 느슨한 부분 수열이나 병음 표기가 사용자가 지정한 적 없는 파일까지 제거하게 됩니다.
3. **단독 콜론은 무시됩니다** — 뒤에 아무것도 없는 `:`는 연산자가 아니며 검색어에서 그냥 버려집니다.
4. **드라이브 콜론은 다릅니다** — 드라이브 문자는 콜론 뒤에 오고(`d:`, [4장](#_4-경로-모드-및-드라이브-범위-지정) 참조), 제외는 콜론 앞에 옵니다(`:temp`). 이 둘은 절대 혼동될 수 없으며, 단어 안의 콜론(`c:\path`)은 일반 텍스트입니다.
5. **정규식 절은 검색어를 읽는 다른 어떤 처리보다 먼저 분리됩니다** — 바로 이것이 백슬래시와 슬래시가 경로로 오인되지 않게 해 주며, 절이 검색어의 어디에나 올 수 있다는 뜻입니다(`/\.md$/ report`와 `report /\.md$/`는 같은 검색입니다).

**연산자 조합 예시**:

- `report :draft`: `report`를 포함하는 이름을 찾고, 이름에 `draft`가 포함된 항목은 모두 제거합니다.
- `IMG :png :gif`: `IMG`를 포함하는 이름을 찾으면서 `png`와 `gif` 파일을 모두 제거합니다. 두 제외는 AND로 결합되므로 어느 쪽도 포함하지 않는 이름만 남습니다.
- `log :temp :bak`: 임시 파일도 백업 파일도 아닌 `log` 파일만 남깁니다.

### 정규식 (`/.../`)

슬래시 사이에 .NET 정규식을 작성하면 설명한 그대로 파일 **이름**과 정확히 매칭됩니다:

```text
/^report.*\.md$/
```

이는 `report`로 시작하고 `.md`로 끝나는 이름을 찾습니다. 이 절은 검색어의 나머지 부분과 AND로 결합되므로 `report /\.pdf$/`는 `report` 매칭 결과 중에서 PDF만 남깁니다.

알아 둘 만한 점이 네 가지 있습니다:

- **매칭 대상은 경로가 아니라 이름입니다**. 파일 내용도 아닙니다. 폴더를 대상으로 하려면 경로 검색어를 사용하세요.
- **병음 별칭을 거치지 않습니다.** 정규식은 이름에 실제로 들어 있는 문자를 설명하므로, 중국어 이름은 병음 표기가 아니라 그 이름 자체의 문자로 매칭됩니다.
- **슬래시는 구분자이고 `\`는 이스케이프입니다.** 리터럴 점에는 `\.`를 씁니다(`.` 단독은 임의의 문자 하나를 의미합니다). 리터럴 슬래시를 매칭하려면 `\/`를 씁니다. `/`는 Windows의 대체 경로 구분자이기도 하므로, 절은 `/`로 열고 `/`로 닫는 단어 전체여야 하며, 내부의 이스케이프되지 않은 `/`는 절을 닫아 버립니다. 그래서 `C:/Users/me`, `/mnt/c/Users`, `/usr/local/` 같은 슬래시 경로는 정규식이 아니라 일반 경로로 처리됩니다. 닫히지 않은 절은 검색어의 나머지를 삼키지 않고 일반 텍스트로 취급됩니다.
- **정규식은 검색어처럼 가속할 수 없습니다**. 고정 문자열이 아니기 때문입니다. Lertaro는 그 식이 요구하는 가장 긴 리터럴 문자 연속을 뽑아내어(`/\.exe$/`에서는 `.exe`, `/^(ogg|mp3)$/`에서는 아무것도 나오지 않습니다) 실제 식을 실행하기 전에 대부분의 후보를 건너뛰는 데 사용합니다. 리터럴이 없는 정규식과 함께 일반 단어를 덧붙이는 것이 그러한 검색을 빠르게 유지하는 확실한 방법입니다.

## 4. 경로 모드 및 드라이브 범위 지정

### 드라이브 지정

드라이브 문자 뒤에 콜론을 붙여 검색어를 시작하면 결과를 해당 드라이브로 엄격하게 제한합니다:

```text
d: report
```

드라이브 지정은 **독립된 두 문자 토큰**이어야 합니다. 즉 콜론 뒤에 공백이 와야 합니다. `d:report`는 더 이상 드라이브 지정이 아니라 리터럴 텍스트 `d:report`를 검색하는 일반 검색어입니다. 처음 두 문자로 드라이브를 추측하면 잘못된 결과가 발생했기 때문입니다. ASCII 문자만 인식하므로 `中: x`도 드라이브가 아닙니다.

### 전체 경로 모드

검색어에 경로 구분 기호(`\` 또는 `/`)가 포함되어 있으면 Lertaro가 자동으로 전체 경로 매칭 모드로 전환합니다:

```text
D:\Projects\Lertaro
```

경로 구분 기호로 끝나면(예: `D:\Projects\`) 해당 폴더 **내부**의 직속 항목을 검색합니다.

> [!NOTE]
> 플러그인 토큰도 `\`로 시작합니다(예: `\audio`). 토큰은 경로 모드를 결정하기 전에 검색어에서 분리되므로, 토큰과 일반 단어만 포함된 검색어(`report \audio`)는 일반 이름 검색으로 유지됩니다. 경로 모드는 남은 텍스트에 구분 기호가 있을 때만 작동합니다.

### 상위 폴더 매칭 대체

파일 이름만으로 검색해 결과 용량을 채우지 못하면, Lertaro는 특별한 문법 없이 파일 이름에서 매칭되지 않은 검색어를 사용해 상위 폴더 이름을 자동으로 매칭합니다:

```text
d01j dcj
```

`dcj`가 파일 자체의 이름에는 전혀 나타나지 않더라도, Lertaro는 이름이 (또는 별칭이) `dcj`인 폴더에 있는 `d01j.txt`를 찾아냅니다.

> [!NOTE]
> 이를 위해서는 최소 하나의 검색어가 파일 이름 자체와 매칭되어야 하며, 이름만으로 찾은 결과가 충분하지 않을 때만 작동합니다. 대체 결과는 항상 직접적인 파일 이름 매칭 결과 뒤에 순위가 매겨집니다.

## 5. 쿼리 토큰: 정렬 및 필터링

쿼리 토큰은 Windows 파일 이름에 나타날 수 없는 문자로 시작하는 단어이므로 검색하려는 텍스트와 절대 혼동되지 않습니다. 두 가지 계열이 있습니다:

| 계열 | 트리거 | 예시 | 소유자 |
| :--- | :--- | :--- | :--- |
| 정렬 / 필터 | `<`와 `>` | `<s>20m` | `CoreExtensions` 플러그인 |
| 플러그인 토큰 | 설정된 **플러그인 쿼리 토큰 접두 문자**(기본값 `\`) | `\audio` | 해당 토큰을 차지한 플러그인 |

### 토큰은 검색어 어디에나 올 수 있습니다

토큰은 반드시 끝에 올 필요가 **없습니다**. 다음은 모두 동일합니다:

```text
report <s>20m \audio
<s>20m report \audio
\audio report <s>20m
```

토큰은 **단어 전체**이면서 단어의 시작일 때만 인정됩니다. 즉 `abc\def`는 토큰이 아니라 일반 텍스트입니다.

### 정렬 및 임계값 (`<`와 `>`)

첫 번째 문자는 정렬 방향을, 그다음 문자는 속성을 결정합니다:

| 토큰 | 의미 |
| :--- | :--- |
| `<s` | 크기순 정렬, 작은 것 먼저 |
| `>s` | 크기순 정렬, 큰 것 먼저 |
| `<c` / `>c` | 생성 시간순 정렬, 오래된 것 / 최신 것 먼저 |
| `<m` / `>m` | 수정 시간순 정렬, 오래된 것 / 최신 것 먼저 |
| `<a` / `>a` | 액세스 시간순 정렬, 오래된 것 / 최신 것 먼저 |
| `<f` / `>f` | 폴더 먼저 / 파일 먼저 정렬 |

두 번째 트리거와 임계값을 추가하면 그중 한쪽만 남길 수 있습니다:

| 토큰 | 의미 |
| :--- | :--- |
| `<s>20m` | 20MB보다 큰 파일 |
| `<s<20m` | 20MB보다 작은 파일 |
| `>c>2008.8.3` | 2008-08-03 이후에 생성된 항목 |

두 번째 트리거는 정렬 화살표의 반복이 아니라 **비교**입니다. `>`는 항상 하한을, `<`는 항상 상한을 의미합니다.

크기에는 `k`, `m`, `g`, `t` 접미사(2진 단위이므로 `1m`은 1MiB) 또는 순수 바이트 수를 사용할 수 있습니다. 폴더/파일 키의 임계값은 `f` / `folder` / `dir`을 사용합니다.

날짜는 반드시 **연도를 먼저** 써야 합니다. 다음 형식이 허용됩니다(두 자리 연도는 `20xx`로 해석됩니다):

| 구분 기호 | 연도 자릿수 | 월/일 자릿수 | 예시 |
| :--- | :--- | :--- | :--- |
| `-` | 4 또는 2 | 0 채움 여부 무관 | `2003-01-03`, `2003-1-3`, `03-1-3` |
| `.` | 4 또는 2 | 0 채움 여부 무관 | `2003.01.03`, `2003.1.3`, `03.1.3` |
| `/` | 4 또는 2 | 0 채움 여부 무관 | `2003/01/03`, `2003/1/3`, `03/1/3` |
| 없음 | 4 | — | `20030103` |

구분 기호를 섞을 수 없으며(`2003-08.03`은 날짜가 아닙니다), 월을 먼저 읽는 `01-03-2003` 형식도 허용되지 않습니다. 순서는 항상 연, 월, 일이므로 하나의 검색어가 두 대의 컴퓨터에서 서로 다른 날짜를 의미하는 일은 없습니다. 연도만 있는 형식(`2008`)과 연-월 형식(`2008.8`)도 허용되며, 각각 "2008년 동안"과 "2008년 8월 동안"을 의미합니다.

### 플러그인 토큰 (`\`)

플러그인 토큰은 플러그인이 제공하며, 각 토큰의 의미는 해당 플러그인이 결정합니다. 기본 제공되는 `CoreExtensions` 플러그인은 파일 카테고리 필터를 제공합니다:

- `\doc`: 문서 (`*.doc; *.docx; *.pdf; *.txt; *.ppt; *.pptx; *.xls; *.xlsx; *.csv; *.rtf; *.md; *.wps`)
- `\img`: 이미지 (`*.jpg; *.jpeg; *.png; *.gif; *.bmp; *.webp; *.ico; *.svg; *.tif; *.tiff; *.psd; *.ai`)
- `\video`: 동영상 (`*.mp4; *.mkv; *.avi; *.mov; *.wmv; *.flv; *.m4v; *.webm; *.3gp; *.rmvb; *.ts`)
- `\audio`: 오디오 (`*.mp3; *.wav; *.flac; *.aac; *.ogg; *.m4a; *.wma; *.ape`)
- `\zip`: 압축 파일 (`*.zip; *.rar; *.7z; *.tar; *.gz; *.bz2; *.xz; *.iso; *.wim; *.esd`)

**예시**:

- `financial \doc`: 문서 중에서 "financial"을 검색합니다.
- `wallpaper \img`: 이미지 중에서 "wallpaper"를 검색합니다.

**설정 → 플러그인 → CoreExtensions**에서 카테고리 이름을 바꾸거나, 각 카테고리가 포함하는 확장자를 변경하거나, 직접 추가할 수 있습니다. 키워드 자체는 최장 일치 우선으로 매칭되므로 `\a` 규칙과 `\audio` 규칙이 공존해도 `\audio`가 이깁니다.

접두 문자는 **설정 → 일반 → 시스템 → 플러그인 쿼리 토큰 접두 문자**에서 설정할 수 있습니다. 비워 둘 수 없고, `<`나 `>`일 수 없으며, 다른 플러그인 자체의 접두 문자와 같아서도 안 됩니다. 이러한 충돌이 발생하면 한쪽 제공자가 조용히 이기게 두지 않고 설정에서 충돌을 보고합니다.

전체 검색 창 왼쪽의 유형 필터 사이드바는 같은 플러그인의 **검색 필터** 그룹에서 별도로 설정합니다. 사이드바 필터 이름은 표시 전용이며, 접두 문자 참조는 사이드바 필터 규칙 안에서만 해석되고 비활성화된 사용자 지정 필터를 포함한 **사용자 지정 필터** 목록의 키워드를 가리킵니다.

### 토큰 연쇄 결합

토큰은 독립된 단어이므로 하나의 검색어에 여러 개를 넣을 수 있고, 각각 차례로 적용됩니다:

- `report \doc >m`: "report"를 검색하고, 문서만 남기며, 수정 시간순(최신 먼저)으로 정렬합니다.
- `backup \zip <s`: "backup"을 검색하고, `.zip` 압축 파일만 남기며, 크기순(작은 것 먼저)으로 정렬합니다.
- `icon \img <s>1m`: "icon"을 검색하고, 1MB보다 큰 이미지만 남기며, 작은 것 먼저 정렬합니다.

## 6. 특수 검색 기능

### 한 번의 검색에서 제외 규칙 무시

검색어 앞에 `*`를 붙이면 설정을 변경하지 않고 이번 한 번의 검색에서 [**제외 규칙**](./settings/index-drives#_5-제외-규칙-exclusions)에 설정된 경로 제외, glob, 정규식을 일시적으로 무시할 수 있습니다:

```text
*node_modules
```

맨 앞의 `*`는 매칭 전에 제거됩니다. 이는 이미 인덱싱된 파일만 다시 불러옵니다(네트워크/WSL 드라이브에서 한 번도 인덱싱되지 않은 제외 경로는 나타나지 않습니다). 시스템/숨김 파일 필터는 계속 활성 상태로 유지됩니다. 참고로 이는 앱 자체의 제외 **규칙**이며, 검색어의 `:` 제외 항목과는 다른 것입니다.

### 결과 유형 트리거

**설정 → 일반 → 퀵 검색 윈도우 → 결과 유형 우선순위**에서 특정 결과 유형(응용 프로그램, 설정, 파일 카테고리, 플러그인, 파일 등)에 대한 1글자 **트리거**를 설정할 수 있습니다.

퀵 검색 윈도우에서 트리거를 맨 첫 문자로 입력하면 해당 결과 유형만 표시되고 나머지는 모두 숨겨집니다:

```text
;vs
```

`;`가 "응용 프로그램"에 할당되어 있다면 위 검색어는 응용 프로그램 중에서만 Visual Studio를 검색합니다. 트리거는 앞에 아무것도 없는 첫 번째 문자여야 하며, 퀵 검색 창과 인라인 검색 창에만 적용됩니다. 두 창 모두에서 기록과 즐겨찾기는 트리거와 관계없이 항상 맨 위에 고정됩니다.

> [!NOTE]
> 트리거는 검색어의 첫 번째 문자여야 합니다. 앞에 플러그인 토큰이나 정렬 토큰이 있으면(`\img ;vs`) 검색어가 더 이상 트리거로 시작하지 않으므로 트리거가 인식되지 않습니다.

## 7. 다국어 별칭

### 중국어 파일 이름: 병음 별칭

`PinyinAlias` 플러그인이 기본 포함되어 있어, 중국어 파일 이름을 별도 설정 없이 바로 병음으로 검색할 수 있습니다:

- **전체 병음**: `chongqing`을 입력하면 `重庆.docx`에 매칭됩니다.
- **병음 첫 글자**: `cq`를 입력해도 `重庆.docx`에 매칭되며, `wzry`를 입력하면 `王者荣耀.exe`에 매칭됩니다.
- **다음자(多音字)**: 일반적인 발음이 자동으로 인덱싱됩니다(예: `重庆`은 `chongqing`과 `zhongqing` 모두에 매칭됩니다).

**설정 → 플러그인**에서 `PinyinAlias`가 활성화되어 있는지 확인할 수 있습니다.

### 스페인어 파일 이름: 악센트 별칭

`SpanishAlias` 플러그인이 기본 포함되어 있어, 스페인어 악센트 문자(`á`, `é`, `í`, `ó`, `ú`, `ü`, `ñ`)가 포함된 파일 이름을 악센트 없는 ASCII 문자로 그대로 검색할 수 있습니다:

- `cancion`을 입력하면 `Canción.mp3`에 매칭됩니다.
- `nino`를 입력하면 `Niño.txt`에 매칭됩니다.
- `ciguena`를 입력하면 `Cigüeña.png`에 매칭됩니다.

매칭된 문자(원래 이름의 악센트 모음 포함)는 정확하게 강조 표시됩니다. 플러그인은 **설정 → 플러그인**에서 관리합니다.

## 8. FAQ 및 즐겨찾기

### 사용자 지정 별칭이 아닌 즐겨찾기

Lertaro는 범용적인 "사용자 지정 검색 별칭/매크로" 기능을 제공하지 않습니다. 가장 가까운 기본 기능은 다음과 같습니다:

- [**즐겨찾기**](./settings/favorites): 파일, 폴더, URL을 원하는 표시 이름으로 고정하면 해당 사용자 지정 제목으로 검색할 수 있습니다(결과에 ★ 아이콘으로 표시).
- **파일 필터**([**인스턴트 답변**](./instant-answers#_5-파일-필터) 참조): 트리거 키워드를 원하는 폴더에 바인딩한 뒤 퀵 검색 창에서 `keyword term`을 입력하면 일반 인덱스 검색이 해당 폴더로 제한됩니다.

사용자 지정 키워드로 스크립트를 실행하거나 프로그램을 시작하려면 [**사용자 지정 명령**](./instant-answers#_6-커스텀-명령어)을 참조하세요.
