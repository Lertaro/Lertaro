# アクションメニューとプレビュー

## アクションメニュー

すべての検索結果 (ファイル、フォルダー、アプリ) には、「開く」以外にも一連のアクションが用意されています。エクスプローラーで開く場所を表示する、パスをコピーする、管理者として実行する、ファイル自体をカット/コピー/貼り付けする、削除する (ごみ箱へ) または完全に削除する、そしてプラグインが追加するもの (例えば、カスケードするサブメニューも含めた Windows シェルの右クリックメニューそのもの) などです。

**アクションメニューを開く** ホットキー (既定では `Ctrl+O`)、または選択した検索結果に対する実際の右矢印キーで開きます。メニュー内では:

- **次/前のアイテム** — 矢印キー、または自分で設定した[次/前のアイテム用ホットキー](./hotkeys)で、アクションリストのハイライトを上下に移動します。カスタムの割り当て (単なる `Tab` キーのようなものでも) は、メイン検索結果リストとまったく同じようにここでも機能します。
- サブメニューを持つ項目 (「送る」のようなシェルのカスケードメニューなど) では **右矢印キー / Enter** で中に入り、**左矢印キー** または (検索ボックスが空の状態での) **Backspace** で 1 階層戻ります。
- **Escape** はアクションメニューを終了します。ただし、アクションリストを絞り込むために何か入力していた場合は、まず検索ボックスをクリアします。
- 入力すると、検索結果を絞り込むのと同じように、名前で表示中のアクションを絞り込めます。

## フルウィンドウの結果グリッド

検索結果をダブルクリックすると通常は Enter キーを押したときと同様に開きますが、一つだけ例外があります。**パス** 列をダブルクリックすると、代わりにその検索結果を含むフォルダーがエクスプローラーで開きます。これは行のどこであっても `Ctrl` + Enter を押したときと同じ動作です。プラグイン独自のカスタム列でも、同種のダブルクリックの上書き動作を独自に定義できます。

グリッドは一致したものを一定件数で打ち切らずすべて保持し、検索が終わってから一度に表示されるのではなく、結果が届いた順に埋まっていきます。大きなドライブでの範囲の広いクエリは数秒かかることがありますが、その間も行はそのまま操作できます。方向キーの移動は両端で折り返します。先頭行で ↑ を押すと最終行へ、最終行で ↓ を押すと先頭行へ戻ります。

このウィンドウにタイトルバーはなく、ヘッダー部分がそのままドラッグ領域です。検索ボックスとウィンドウボタン以外のどこを押してドラッグしてもウィンドウを移動できます。ポインターがヘッダー上にある間は上部にグリップがフェードインし、どこをつかめるかを示します。

## QuickLook プレビュー

選択した検索結果に対して **QuickLook** ホットキー (既定では `Alt+P`) を押すと、検索ウィンドウの隣にドッキングされたプレビューパネルが開きます。画像、ドキュメント、その他プレビュー可能なファイル形式が、Lertaro から離れることなくレンダリングされます。もう一度押す (または QuickLook がプレビューできない検索結果に移動する) と閉じます。

フォルダーのプレビューには直下の項目が最大 30 件まで、ファイルまたはフォルダーのアイコンとともに表示されます。Windows エクスプローラーで隠し項目を表示する設定にしていても、このプレビューでは隠し項目とシステム項目が除外されます。

音声・動画ファイル — WPF に組み込まれたメディア再生機能が追加のコーデックなしでサポートする形式 (MP4、WMV、AVI、MOV、MP3、WAV、WMA、その他いくつか) — は、プレビューが開くと同時に自動再生され、静的なサムネイルの代わりに小さなテーマ対応のトランスポートバー (再生/一時停止、シーク、現在/合計時間、ミュート) が表示されます。別の検索結果に移動するか、プレビューを閉じると再生は即座に停止します。特定のコーデックがデコードできないファイルは、静的なサムネイルにフォールバックします。

プレビューウィンドウのサイズは固定で、ユーザーが設定変更できます。詳しくは [設定 → 一般 → プレビュー](./settings/general#プレビュー) を参照してください。このサイズは、現在表示されている検索結果の件数とは無関係です。どのようなサイズに設定しても、Lertaro はプレビューウィンドウが常に画面内に収まるようにします。検索ウィンドウの隣に収まらない場合は空きのある側にドッキングし、設定したサイズがモニターの使用可能領域より大きい場合は、画面からはみ出さないよう縮小して表示されます。

プレビュー対象のファイルが独自のネイティブハンドラーによるポップアップ表示を必要とする場合 — よくあるのは Word や Excel が暗号化されたドキュメントに対してパスワードを求める場合です — クイックウィンドウとプレビューパネルの両方は、そのポップアップが開いている間は自らを非表示にします。そうしないと、ポップアップがウィンドウの背後に隠れて操作できなくなってしまうためです。これは Lertaro が閉じたりクラッシュしたりしたわけではありません。ポップアップに対応 (パスワードを入力する、閉じるなど、求められている操作) すれば、検索テキストや選択状態も含めて、両方のウィンドウはそのままの状態で元に戻ります。

プレビューウィンドウのヘッダー自体が、プレビュー中のファイルのドラッグ元です。エクスプローラーやエディター、その他任意のドロップ先へドラッグすると、検索ウィンドウから結果行をドラッグしたのとまったく同じように振る舞います。

クイックウィンドウからフルウィンドウを開くと、プレビューの表示状態が引き継がれるため、開いていたプレビューはそのまま開いた状態になります。

### QuickLook による外部プレビュー (任意)

これは名前は同じですが、上記の組み込みプレビューパネルとは別のものです。**QuickLook** という名前の、別のサードパーティ製アプリケーション ([GitHub 上の QL-Win/QuickLook](https://github.com/QL-Win/QuickLook)、GPL ライセンス) を自分でインストールする必要があります。Lertaro にはバンドルされていません。

QuickLook がインストールされ実行中であれば、バンドルされている (試験的な) **QuickLook Bridge** プラグイン — [設定 → プラグイン](./settings/plugins) の下にある他のプラグインと同様に表示され、有効/無効を切り替えられます — が、専用の名前付きパイプ経由で QuickLook に接続し、上記で説明したすべての組み込みプレビュー種別に優先してプレビューを引き継ぎます。これが有効な間、Lertaro 自身のプレビューパネルは非表示になり、QuickLook 自身のフローティングウィンドウが、そのパネルが本来占めていたはずの位置にちょうど移動してきます — 見た目としては「プレビューパネルが QuickLook になった」ように見えますが、技術的には QuickLook のウィンドウは完全に独立したトップレベルウィンドウのままで、Lertaro がそれを追従させて再配置しているだけです。

アクションメニューの項目 **Preview in QuickLook** を使うと、他のプレビュー種別が本来優先されるはずの検索結果であっても、手動で QuickLook に送ってプレビューできます。

これは公開された連携 API ではなく、QuickLook 自身の (非公開で文書化されていない) プロセス間通信プロトコルに完全に依存しているため、将来の QuickLook のリリースでこのプロトコルが変更され、この連携が予告なく壊れる可能性があります。QuickLook をアンインストールしたり終了したりしても、それ以外の部分には影響はありません。Lertaro は単純に自身の組み込みプレビュー種別にフォールバックします。
