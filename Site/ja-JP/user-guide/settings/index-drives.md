# インデックス管理

インデックス設定画面では、ローカルドライブ、ネットワーク共有、WSL、個別フォルダーに対するインデックス作成範囲、更新スケジュール、および除外ルールを細かく制御します。画面上部には **ローカルドライブ**、**ネットワークドライブ**、**WSL**（該当環境検出時のみ）、**フォルダー**、**除外ルール** の 5 つのタブが配置されています。

## 1. ローカルドライブ（Local Drives）

- **ステータスサマリー**：現在インデックス化されている物理ドライブ数と総アイテム数が表示され、全ドライブの一括再構築を行う **インデックス再構築** ボタンが配置されています。
- **ドライブ一覧行**：
  - **有効/無効チェックボックス**：パーティションごとにインデックス作成を個別に切り替え。
  - **ファイルシステムと状態**：ファイルシステムの種類（NTFS、ReFS、FAT32、exFAT 等）、稼働状態、インデックス済みアイテム数を表示。
  - **個別ドライブ操作**：**再構築** と **削除** ボタン。スキャン実行中は動的に **停止** ボタンが表示されます。
- **リアルタイム監視**：NTFS / ReFS は Windows の USN 変更ジャーナルを読み取ってミリ秒単位で同期し、FAT32 / exFAT はファイル変更イベントを監視します。
- **無停止での再構築**：ドライブの再構築中も、新規インデックスが完成するまでは既存のインデックスが検索に応答し続けるため、検索が途切れることはありません。再起動等で中断されても次回起動時に続きから再開されます。

## 2. ネットワークドライブ（Network Drives）

- **ネットワーク共有の対応**：マウント済みの Windows ネットワークドライブ（SMB / NAS）を一覧表示。
- **更新モード（Refresh Mode）**：ローカルの変更ジャーナルが存在しないため、定期スキャン周期を設定可能：
  - **手動** —— 「インデックス再構築」クリック時のみスキャン。
  - **15 分ごと** —— 頻繁に更新される共有向け。
  - **1 時間ごと** —— 標準的な定期更新。
  - **毎日** —— アーカイブ用ストレージ向け。
- **シンボリックリンク循環保護**：NAS 上の循環シンボリックリンクやジャンクションによる無限ループを防ぐため、ループ検知エンジンが重複パスを自動スキップします。

## 3. WSL（Linux 用 Windows サブシステム）

WSL ディストリビューションがインストールされている場合に自動的に表示されます。

- **自動検出**：Ubuntu、Debian、Arch などのインストール済みディストリビューションを自動認識。
- **状態と更新**：ネットワークドライブと同様のステータス管理と更新モード（手動 / 15 分ごと / 1 時間ごと / 毎日）を提供。
- **ゼロ I/O 検索**：WSL ファイルの検索時はメモリインデックスを直接参照し、Linux サブシステムを起動させたり負荷をかけたりしません。

## 4. フォルダー（Folders）

ドライブ全体ではなく、特定の作業フォルダーのみを対象にしたい場合に利用します。

- **複数選択での追加**：**フォルダーを追加** をクリックしてピッカーを開き、`Ctrl` または `Shift` キーを押しながら複数のフォルダーを一括追加可能。
- **UNC パスのサポート**：`\\server\share\projects` のようなネットワーク UNC パスも直接登録可能。
- **個別更新スケジュール**：各フォルダーごとに独立した有効スイッチ、アイテム数、更新モード（手動 / 15 分ごと / 1 時間ごと / 毎日）を設定できます。

## 5. 除外ルール（Exclusions）

除外ルールは検索結果の絞り込みと、ネットワーク・WSL・フォルダーの走査範囲の限定に使われます。ローカルドライブのインデックス作成は止まりません。ローカルのボリュームは常に全体が走査されるため、ここに `E:\` と書いても結果が隠れるだけです。ローカルドライブのインデックス作成を止めるには、上の**ローカルドライブ**タブで無効にしてください。ルールはサブタブのない**一覧**にまとまっています。各ルールは照合方法と段階の組み合わせで、照合方法は入力の書き方から自動判定され、入力欄に**判定:** で表示されます。

- **完全パス**：ドライブ文字（`D:\Cache`）、UNC パス（`\\server\share`）、環境変数（`%ProgramData%`、`%APPDATA%`）、`shell:` の仮想パスで始まります。そのフォルダーとすべての子項目を対象にします。
- **ワイルドカード**：それ以外の書き方はすべてワイルドカードです。`*` は 1 階層内の任意文字（`*.log`）、`?` は 1 文字、`**` は再帰（`**\node_modules\**`）に一致します。区切り文字を含まないルールは任意の階層にある名前に一致し（`node_modules`、`*.tmp`）、区切り文字を含むルールはドライブのルートから確定します。`Listary\abc` は `C:\Listary\abc` とその中身に一致しますが、`D:\work\Listary\abc` には一致しません。
- **正規表現**：スラッシュで囲みます。例：ドット始まりの隠しファイルは `/^\./`、Office の一時ロックファイルは `/~\$/`。完全パスとファイル名のどちらにも部分一致で評価されます。ワイルドカードで済むなら正規表現は避けてください。正規表現は毎回解釈実行するためコストが高くなります。

**段階**は扱いを決めます。**除外**は表示せず、**低・標準・高**は並び順だけを変えます。高優先のルールはチェックで最上位に固定できます。段階は行の右にあるドロップダウンで選べますし、先頭の接頭辞でも書けます：`!` 除外、`-` 低、`+` 高、なしは標準。行頭にバックスラッシュを置くと接頭辞を文字として扱います。

> [!NOTE]
> 接頭辞を取り除くのは**追加**入力欄と**一括編集**だけです。既存のルールを行内編集した場合、テキストは文字どおり扱われるので、段階はドロップダウンで変更してください。ワイルドカードの中に残った `!` はパスの文字とみなされ、Windows のパスに `!` は含まれないため、そのルールは何にも一致しません。ページはエラーを表示しません。

ローカルディスクは検索時に適用し、ネットワークディスク・WSL・カスタムフォルダーはインデックス作成時に除外項目を飛ばし、設定を適用後に更新します。除外ルールが優先度ルールに覆されると、一覧の上に競合バナーが出て、覆されたルールは効きません。

> [!TIP]
> ルールは**個別追加**と**テキストによる一括インポート/エクスポート**の両方に対応しています。**リストから生成** でルールをエクスポートし、編集後に **リストへ適用** をクリックして一括反映できます。一括編集のテキストに解釈できない行があると、いずれの行も適用されず、テキストは修正を待って欄に残ります。
